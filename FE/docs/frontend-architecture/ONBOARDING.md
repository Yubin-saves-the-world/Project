# 로그인·가입 화면 구현 기준

2026-10-07 현재 Figma의 `00 Login`, `01 회원가입`, `02 신체정보`, `03 체형분석 입력` 네 화면을 기준으로 구현했다. 예전의 근사 디자인 설명은 이 문서로 대체한다. 디자인 원본 자체는 변경하지 않았다.

## 디자인 확인

Figma MCP의 Starter 사용량 한도로 상세 조회가 막혀, 네이티브 Figma에서 읽기 전용 로컬 플러그인으로 현재 프레임의 좌표·색·텍스트 스타일·SVG·PNG를 추출했다. 원본은 [현재 Figma 자료](../figma-reference/current/design.json)에 보관한다. 393×852 기준으로 흰색 배경, `#4361EE`, 제목 30px, 한글 입력 라벨 15px, 입력 본문 14px, 24px 좌우 여백과 원본 아이콘을 적용했다. 단계 표시·설명 문구·비밀번호 확인란을 제거하고 원본의 화면 순서와 배치를 따른다. 작은 화면·큰 글꼴·키보드에서는 스크롤로 접근한다.

원본 서체인 Pretendard Variable의 400·500 인스턴스를 번들했다. Flutter의 가변 폰트 굵기 매칭 차이를 줄이기 위해 정적 인스턴스로 변환했으며, OFL의 예약 이름 조건에 따라 파생 파일의 이름은 CapstoneUI로 변경했다. 라이선스는 `assets/fonts/Pretendard-OFL.txt`에 보관한다. 텍스트 가장자리 렌더링은 Figma와 Flutter 엔진에 따라 조금 다를 수 있다.

## 동작과 사용자 결정

- 첫 화면은 `/login`; 회원가입 링크로 `/signup`에 진입한다. 뒤로 이동해도 가입 초안을 유지한다.
- 회원가입 입력은 닉네임·이메일·인증번호·비밀번호다. 이메일 입력칸의 ‘인증번호 받기’로 발급한다. 발급 후 라벨 오른쪽에 남은 시간이 표시되며, 이메일을 바꾸면 인증번호와 시간이 초기화된다. **개발용 번호 `123456`**, 발급 이메일에 한정, 5분 유효, 오입력 5회 제한, 재발급 가능. 실제 메일은 발송하지 않는다. 최종 API에 인증번호 엔드포인트가 없으므로 서버 인증 증명이나 가입 요청 필드로 전송하지 않는다.
- ‘다음’을 누르면 필수 동의 4개를 별도 창에서 받는다. 이용약관·개인정보·신체 사진·AI 처리 모두 동의해야 가입한다. 문구는 개발용 안내이며 정식 약관은 서비스 연결 전에 필요하다.
- 신체정보는 키 100~250cm, 몸무게 30~250kg, 나이 10~100세와 성별·운동 목적·주간 운동 횟수·경력을 저장한다. 187·85·18은 입력 예시이며 실제 값으로 자동 저장하지 않는다. 성별은 남·여만 표시한다. 원본에서 선택된 남·근육 키우기·2~3회·3개월 미만을 초기 선택으로 적용한다. 기존 데이터의 `none`은 모델 호환만 유지하고 새 입력으로 저장할 수 없다.
- 사용자가 지정한 범위 상한값 매핑: `0 ~ 1회→1`, `2 ~ 3회→3`, `4 ~ 5회→5`, `6~7회→7`. API에는 정수로 저장한다.
- 사진 분석 카드를 누르면 정면 필수·측면 선택 사진을 입력한다. 카메라/앨범 선택·미리보기·삭제·취소를 지원한다. 목표 사진은 선택이다. 사진은 EXIF 보정 후 긴 변 1024px JPEG로 준비하고 기기 내 앱 영역에 보관한다.
- 글로 설명하기 카드를 누르면 최대 500자로 입력한다. 텍스트 분석은 최종 문서의 2차 기능이며 현재는 입력 흐름만 테스트한다.
- ‘분석 시작’은 선택한 입력을 검증·저장하고 홈으로 이동한다. 백엔드·업로드·AI 분석이 연결되지 않아 실제 분석 결과를 생성하지 않는다.
- 신체정보 저장으로 온보딩 완료 상태를 유지한다. 로그아웃은 기존 계정·기록을 유지하고 로그인으로 이동한다. 기기 내 로그인은 저장된 이메일과 입력 형식으로 화면 이동만 확인하며 비밀번호 검증·JWT를 제공하지 않는다. 비밀번호는 디스크에 저장하지 않는다.
- 구글·카카오·비밀번호 찾기 버튼은 원본대로 배치하고 서비스 미연결 안내를 제공한다. OAuth SDK·서버 인증·메일 발송은 이후 연결한다.

## API 연결

최종 문서 원본은 `docs/final-specs`에 유지한다. 실제 연동은 `OnboardingRepository`를 교체해 `VitalityApp`에 주입한다. `register`는 가입, `login`은 인증 및 내 정보 조회, `saveProfile`은 최초 POST/수정 PATCH다. 토큰 기반 조회 후 동의·신체정보·홈 상태를 분기한다. 현재 개발용 OTP는 서버의 중복 계정 방지나 이메일 소유 증명이 아니다.

## 최신 수정 반영 (2026-10-07 오후)

- 로그인·가입의 한글 라벨, 컬러 구글/카카오 로고, 가입 이메일 칸 내부 인증번호 버튼과 실제 유효 시간 표시를 반영했다. Figma의 `1:58`은 입력 상태 예시이므로 고정하지 않고 개발용 5분 유효 시간을 표시한다.
- 신체정보 섹션 간격 21px, 체형분석 카드 간격 15px, 두 페이지 하단 버튼 y=768을 적용했다.
- 기존 초록색 공통 테마를 파란색 `#4361EE`, 흰색 배경, CapstoneUI 서체로 통일했다. 소셜·비밀번호 안내, 인증번호 안내, 필수 동의, 사진·목표 사진 입력, 카메라/앨범 선택, 글 입력, 기존 계정의 동의 페이지와 오류·완료 안내가 같은 테마를 따른다. 팝업 모서리 20px, 하단 창 윗모서리 24px, 입력칸·버튼 14px를 사용한다.
- 추가 창 미리보기는 `previews/modals`에 보관했다. 작은 화면·큰 글꼴·키보드에서도 창 내용을 스크롤할 수 있도록 검증한다.

컬러 로고의 SVG는 이미지 패턴 채움을 사용해 Flutter SVG 렌더러에서 표시되지 않았다. 따라서 동일 Figma 벡터 레이어를 8배 PNG로 원본 추출해 같은 크기·위치에 표시한다. SVG 원본도 보관한다.
