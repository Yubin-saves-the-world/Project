# 직접 만드는 반복 주간 일정

현재 작업 프로젝트: `/Users/yubin/StudioProjects/Project/FE`.

## 사용 흐름

첫 진입에는 주 운동 횟수를 기준으로 임의 루틴을 배정하지 않습니다. 홈의 요일은 날짜만 선택하며, 일정 만들기·일정 수정 버튼을 누르면 루틴 편집이 열립니다. 루틴 이름, 종목, 종목별 세트·횟수, 선택적으로 예상 소요 시간을 입력하거나 휴식일을 선택합니다. 다른 요일의 루틴을 복사할 수 있습니다.

앞으로 매주를 선택하면 같은 요일마다 반복됩니다. 처음 일정을 만드는 경우 선택한 주부터 표시되며, 기존 반복 일정의 수정은 선택한 미래 날짜(과거 요일을 선택했다면 오늘) 이후에 반영됩니다. 이번 날짜만은 날짜별 예외로 저장되어 다음 주의 반복 일정에 영향을 주지 않습니다. 명시적으로 지정한 다른 날짜의 예외는 유지됩니다.

이미 완료한 운동 기록은 일정 수정으로 삭제하거나 덮어쓰지 않습니다. 진행 중인 운동에 영향을 주는 일정 변경은 완료 또는 취소 후 가능합니다. 운동 시작은 오늘 일정에 등록된 종목만 가능하고, 사용자가 정한 세트·횟수를 입력창에 가져옵니다.

신체정보의 주 운동 횟수와 실제 선택한 일정은 별도로 관리하며, 홈과 편집 화면에는 권장 횟수 설명을 표시하지 않습니다. 운동을 하지 않는 날도 직접 휴식일로 저장할 수 있습니다. 저장 버튼은 편집 화면 하단에 고정되어 있습니다.

## 데이터 보존과 저장

일정은 계정 이메일별 기존 로컬 저장소에 별도의 `vitality.home.weekly.v1` 네임스페이스에 계정 키를 인코딩해 저장합니다. 요일별 변경 이력과 날짜 예외를 같이 보관합니다. 기존 운동 기록의 키·형식은 유지하며 기존 4개 종목의 인덱스도 바꾸지 않았습니다. 기존 휴식일 설정은 날짜 예외로 읽고, 이전의 휴식일 해제 값만으로 임의 종목을 배정하지 않습니다. 이전 설정 키는 삭제하지 않습니다.

잘못된 일정 데이터 또는 로드 실패는 재시도를 요구하고 저장을 막습니다. 저장 실패 시 현재 일정과 입력한 편집 내용은 유지됩니다.

## 현재 연결 범위

프론트의 계정별 기기 저장이며 다른 기기 동기화·서버 저장은 아직 없습니다. 운동 선택 목록은 백엔드 시드의 24개와 일치하는 로컬 목록이며 서버 exercise_id 연결은 이후 필요합니다. 기존 12개 항목의 번호는 그대로 유지하고, 시드에 없는 5개 항목은 기존 일정·기록 조회 및 편집을 위해 보존합니다. 새 일정에서는 시드의 24개만 선택할 수 있습니다. AI 추천은 새 일정에 자동 적용하지 않습니다. 운동 실행 자체는 기존 미리보기 입력창을 유지합니다.

v0.3의 자동 루틴 배정과 달라진 정책이므로 기획서·API에는 수동 주간 일정, 반복 적용일, 날짜별 예외, 루틴 복사 및 일정 변경 시 기록 보존 정책을 추가해야 합니다.

## 2026-10-20 일정 편집을 별도 페이지로 변경 — 최신 UI 기준

- 홈의 일정 만들기·일정 수정·운동일로 변경은 `MaterialPageRoute`로 전체 페이지를 연다. 상단 뒤로가기와 하단 고정 ‘일정 저장’을 제공한다. 뒤로가기는 초안을 저장하지 않는다. 저장 중에는 중복 저장과 페이지 이탈을 막는다.
- 운동일·휴식일은 기존 앱의 파란색·흰색·둥근 모서리로 구성한 선택 버튼을 쓴다. 입력 순서는 루틴 이름 → 적용 범위 → 예상 소요 시간 → 복사(가능한 경우) → 운동 종목이다. 휴식일에서는 루틴 이름·소요 시간·종목을 숨긴다.
- 운동 종목 24개는 가슴·등·하체·어깨·팔·코어에 각 4개씩 묶는다. 기존 종목 번호와 기록은 유지하며 이전 일정에만 있는 항목은 ‘기존 종목’으로 편집한다.
- 적용 범위·루틴 복사는 선택칸 바로 아래에 여는 둥근 드롭다운(`MenuAnchor`)을 사용한다. 화면 여백이 부족하면 메뉴 위치를 조정한다. 이 결정은 앞선 ‘모든 선택을 하단 시트로’ UI 기록을 대체한다. 소요 시간 휠과 계정 메뉴의 하단 시트는 유지한다.
- 종목 미선택·저장 실패 메시지는 하단 저장 버튼 위에 표시하여 긴 종목 목록 끝까지 이동하지 않아도 확인할 수 있다.
