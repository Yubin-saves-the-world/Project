## 4. 10월 28일 — MOVID 브랜딩·전체 검토·문제 수정

- 시작 화면 캐시를 갱신하면서 기존 계정 데이터가 유지되는지 확인했다.

### 전체 코드·페이지·API 검토

- 주요 페이지의 기능·이동·데이터 전달·로컬/서버 모드 차이를 검토했다.

- 확인된 문제, 기존 정책에 따른 연동 공백, 준비 중 기능, 실제 서버가 필요한 검증을 구분했다.

- 재조회도 실패하면 입력을 유지하고 쓰기를 보류한다.

### 목표 체형 설명 처리

- 설명을 비웠는데 서버에서 기존 설명이 다시 나타나는 상황을 방지했다.
- 현재 API는 설명 생략을 ‘유지’로 해석하고 빈 문자열 삭제를 허용하지 않는다.
- 설명만 삭제하는 기능을 임의로 추가하지 않고 입력 단계에서 제한을 명확히 안내하도록 했다.
- 로컬·테스트 저장소의 설명 생략 의미도 서버와 맞췄다.

### 수동 일정의 새 운동을 서버 기록에 연결

- 서버 모드의 수동 일정도 공통 서버 운동 실행 화면을 사용하도록 했다.
- 서버 목록에서 이름·부위가 유일하게 일치하는 종목을 찾고 상세 정보를 확인한다.
- 기존 카탈로그 인덱스를 서버 종목 ID로 잘못 전송하지 않도록 했다.
- 서버에서 찾지 못하거나 정보가 모호한 종목은 시작 전에 안내한다.
- 완료 후 홈 통계·기록·종목 완료 표시를 갱신하도록 했다.
- 여러 페이지에 걸친 날짜별 완료 기록도 확인하도록 했다.
- 기존 기기 기록·반복 일정·진행 중이던 기기 운동은 보존했다.

### 인증 토큰 보안 저장

- JWT 기본 저장소를 OS 보안 저장소로 변경했다.
- 기존 토큰은 보안 저장 후 확인하고 이전 저장 위치에서 제거하도록 했다.
- 동시 읽기·토큰 이전·로그아웃이 충돌하지 않도록 순서대로 처리했다.
- 보안 저장 실패 시 기존 토큰을 먼저 삭제하거나 일반 설정 저장으로 우회하지 않도록 했다.
- iOS Keychain 설정과 Android 보안 저장 파일의 백업 제외 규칙을 추가했다.
- 별도 일회용 QA 시뮬레이터에서 실제 Keychain 동작을 검증하고 QA 기기를 정리했다.

## 6. 남아 있는 제한·후속 작업

- 현재 일반 앱 빌드 설정은 **로컬 미리보기**다.
- 기본 서버 주소 `http://localhost:8080`은 마지막 점검 시 연결되지 않았다. 다른 주소의 원격 서버가 꺼졌다는 뜻은 아니다.
- 최신 API를 제공하는 테스트 서버에서 실제 메일·DB·사진 저장소·AI를 포함한 전체 왕복 검증이 필요하다.
- 구글·카카오 로그인, 글 체형분석, AI 코치, 알림, 맞춤 식단, 자세 교정은 준비 중이다.
- 실제 보상·쿠폰 발급은 구현 완료로 볼 수 없다.
- 수동 주간 일정과 프로필 아바타의 기기 간 동기화는 구현하지 않았다.
- 과거 기기 운동 기록을 서버로 자동 이관하지 않았다.
- 목표 체형의 기존 설명만 삭제하려면 별도의 API 계약이 필요하다.
- Android 보안 저장소는 빌드까지 확인했으며 실제 Android 기기에서의 런타임 검증은 남아 있다.
