## 2. 최신 사용자 결정 — 기획서와 별도로 유지할 내용

- 처음 앱에 들어오면 임의 운동 루틴을 배정하지 않는다. 사용자가 요일을 직접 눌러 일주일 운동·휴식 일정을 만들고 매주 반복한다. v0.3의 자동 배정과 다른 **후속 변경**이다.
- 일정은 ‘앞으로 매주’와 ‘이번 날짜만’을 지원하고, 다른 요일 루틴 복사를 지원한다. 완료된 운동 기록은 일정 변경으로 삭제·덮어쓰기 하지 않는다.
- 모든 요일에서 휴식일을 직접 지정·해제할 수 있어야 한다. 월·화 등 특정 요일을 막지 않는다.
- 홈은 운동 기록을 요약하고 ‘보기’로 별도 달력 페이지에 들어간다. 달력에서 날짜를 누르면 해당 날짜 운동 기록을 보여준다.
- 홈에서 제거한 별도 날짜 문구·‘이번 주/오늘로’ 같은 조작을 임의로 다시 추가하지 않는다. 휴식일 조작을 날짜 줄 밑의 별도 혼잡한 영역으로 되돌리지 않는다.
- 성별에 ‘미선택’ 옵션은 없다. 성별·운동 목적·주 운동 횟수·운동 기간은 처음부터 선택되어 있지 않아야 한다.
- 키·몸무게·나이는 직접 입력하며 `170 / 65 / 18`은 입력 예시다. 초기 입력값으로 채워 두지 않는다.
- 오류는 해당 입력·선택 항목 가까이에 표시하며 ‘다음’·‘분석 시작’ 버튼을 아래로 밀지 않는다. 로그아웃 후 새 가입에는 이전 입력을 자동으로 남기지 않는다.

- ‘분석 시작만 누르면 홈’이라는 예전 요청은 이전 별도 프로젝트 이력이 있다. 현재 Git 연결 프로젝트는 분석 입력 검증을 보존한 상태로 통합되었다. 검증 우회가 필요하면 현재 동작과 새 요청을 확인하고 수정한다.
- 현재 유지하기로 한 구조: `main()` → `bootstrap()` 및 화면·ViewModel·Repository 분리. 향후 사용할 폴더는 정리 대상이 아니다. 최근 구조 관련 대화는 설명 요청이며 전체 구조 변경 승인이 아니다.

## 3. 구현된 주요 흐름과 제한

### 로그인·가입·비밀번호 찾기

- 로그인, 이메일 가입, 필수 동의, 신체정보, 체형분석 입력, 홈 이동, 로그아웃이 구현되어 있다. 구글·카카오 버튼은 준비 중 안내이며 실제 소셜 인증은 아니다.
- 이메일·닉네임·비밀번호 검증, 인증번호 입력, 발송 안내 모달이 있다. 개발용 인증번호는 **123456**이다. 실제 메일을 보내지 않는다.
- 개발용 인증에는 5분 만료, 잘못 입력 5회 제한, 이메일별 60초 재요청 간격·시간당 5회 제한이 있다. 요청 이력은 해당 인스턴스/화면 세션 범위이며 서버 보안 제한이 아니다.
- 비밀번호 찾기는 개발용 인증 흐름과 기존 서버 모드가 나뉜다. 개발용 완료 화면은 실제 계정 비밀번호 변경을 의미하지 않는다.
- 기존 서버 모드는 F-13의 메일 링크 토큰 계약이다. v0.3의 인증번호 확인→재설정 토큰 발급 API와 차이가 남아 있다. 가입의 이메일 인증 토큰 계약도 백엔드 협의가 필요하다.
- 로그인 자격 증명 오류 5회 후 비밀번호 찾기를 안내하며 네트워크 오류는 횟수에 포함하지 않는다.
- 로컬 가입 저장소는 실제 비밀번호 검증·JWT 발급·중복 계정 관리를 하지 않는다. 저장된 이메일과 입력 조건으로 흐름만 테스트한다.

### 신체정보·분석

- 설문은 ① 키·몸무게·나이·성별 ② 운동 목적·주 운동 횟수 ③ 운동 기간 순서다. 뒤로 가도 입력을 유지하며 마지막 단계에서 저장한다.
- 키·몸무게는 소수 첫째 자리까지, 운동 횟수 마지막 선택은 6을 저장한다. 범위와 상세 검증은 v0.3 및 현재 validator/model을 확인한다.
- 정면/측면 분석 사진과 목표 체형 사진 관련 입력·기기 사진 선택/전처리가 있다. 실제 AI 분석 완료나 서버 추천이 구현됐다고 가정하지 않는다.

### 홈·주간 일정·기록

- 첫 일정은 비어 있다. 홈 요일/일정 만들기에서 이름·종목·세트·횟수·선택 소요 시간을 입력하거나 휴식일로 저장한다.
- 처음 만드는 반복 일정은 선택한 날짜부터 표시된다. 기존 반복 일정의 과거 요일을 수정하면 오늘 이후에 적용하여 과거 계획을 보존한다. 날짜별 예외가 반복 일정보다 우선한다.
- 진행 중 운동에 영향을 주는 일정 변경은 운동 완료/취소 후 가능하다. 오늘 일정에 등록된 종목만 시작할 수 있다.
- 운동 목록은 로컬 목록이다. 기존 12개 종목 인덱스를 유지하며 새 선택 목록은 백엔드 시드의 24개를 사용한다. 시드에 없는 기존 5개 종목은 기존 기록과 일정의 조회·편집을 위해 보존한다. 서버 `exercise_id`가 아니다.
- 운동 실행은 현재 미리보기 입력 방식이다. 세트별 실행·휴식 타이머, 서버 동기화, 실제 AI 추천 적용은 별도 개발이다.
- 일정·기록은 계정 이메일 기준 기기에 저장한다. 새 주간 일정 네임스페이스는 `vitality.home.weekly.v1`이다. 기존 운동 기록 키·형식, 휴식일 데이터와 날짜 예외를 보존한다.
- 저장 실패는 이전 상태와 편집 내용을 유지한다. 데이터 로드 실패를 새 빈 일정으로 덮어쓰지 않는다.

## 5. 실행과 검증

프로젝트 루트에서 실행한다. 환경별 Flutter 실행 파일 위치는 다시 확인한다. 이 기기에서는 `/Users/flutter/bin/flutter`를 사용했다.

```sh
flutter run --dart-define=USE_LOCAL_PREVIEW=true
flutter analyze
flutter test
```

- 기본 `USE_LOCAL_PREVIEW`는 false이며 인증 서버 기본 주소는 `http://localhost:8080`이다. 로컬 미리보기 플래그 없이 실행하고 서버가 없으면 연결 오류가 날 수 있다.
- 실제 서버 사용 시 `--dart-define=API_BASE_URL=...`로 접근 가능한 주소를 설정한다. 모바일의 localhost가 개발 PC라는 가정은 하지 않는다.
- Android 최소 SDK는 28(Android 9), iOS 지원도 유지한다.
- **이전 주간 일정 작업 완료 시** 정적 분석 오류 없음, 전체 테스트 107개 통과·실서버 테스트 1개 미실행, iOS 시뮬레이터 빌드·실행 성공이 보고되었다. v0.3 반영 때는 Android 디버그 APK 빌드도 성공했다. 이번 인수인계 문서 작성에서 앱 테스트·빌드를 다시 실행한 결과는 아니다.
- 아직 커밋되지 않은 앱·테스트·문서 변경이 존재한다. 새 채팅은 `git status`를 새로 확인하고 기존 변경을 보존한다. 커밋·Push는 별도 요청 전까지 하지 않는다.

## 2026-10-20 선택 UI·운동 목록 후속 변경

- 이미지처럼 보이던 기본 드롭다운을 공통 하단 선택 시트로 교체했다. 적용 범위·루틴 복사·계정 메뉴에 적용했다.
