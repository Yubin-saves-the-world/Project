# 운동 기록 연동 (T11)

2026-10-27 · 실제 작업 대상 `/Users/yubin/StudioProjects/Project/FE`.

이전 T10은 `ffafb64` (`feat: 운동 종료 요약 및 다음 종목 이동 구현`)로 커밋하고 origin/main에 Push했다. 아래 T11 변경은 아직 커밋·Push하지 않았다.

## 구현

- 홈 운동 기록의 **보기**와 기존 **운동 기록 탭**에서 월별 서버 기록을 조회한다. 월 이동·날짜 선택·완료 날짜 표시·월간 운동일/기록/세트/볼륨/시간 합계를 제공한다.
- 월 조회는 해당 월의 첫날~마지막 날만 요청한다. 하루 목록은 선택한 날짜만 요청하므로 모두 API의 92일 제한 안이다. 미래 날짜는 선택하지 않으며 앱 복귀/탭 복귀/새로고침 시 오늘 날짜를 갱신한다.
- 완료 날짜 표시는 첫 페이지 items가 아니라 기간 전체의 `summary.workout_dates`를 사용한다. 월간 합계도 서버 summary다. 진행/중단 기록을 완료 통계에 더하지 않는다.
- 날짜 아래 목록은 전체/완료/진행 중/중단 상태별 필터와 더 보기를 제공한다. 자동 중단은 회색과 통계 제외 안내로 구분한다. 월 합계는 목록 필터에 따라 바뀌지 않는다.
- 목록을 누르면 종목·한국 시간 시작 시각·상태·서버 세트 수/볼륨/시간·저장된 메모·세트별 무게/횟수/실제 휴식/완료 여부를 확인한다.
- 완료 기록의 세트는 무게/횟수/실제 휴식/완료 여부를 수정하거나 확인 후 삭제한다. 수정은 최신 `version`을 전송하며 성공 후 서버 상세를 다시 읽는다. 다른 세트의 번호는 재정렬하지 않는다.
- 진행 중 기록은 T9 이어하기로 연결하고, 자동 중단 기록은 읽기 전용으로 표시한다. 6시간이 지난 기록을 이어서 시작하지 않는다.
- 운동 기록 전체 삭제는 세트도 함께 삭제되고 루틴 진행률이 서버에서 다시 계산된다는 확인 후 실행한다. 상세에서 돌아오면 목록·월간 합계·완료 표시를 재조회하며, 홈 복귀/탭 복귀 때 홈 집계도 갱신한다.

## 보존과 오류 처리

기존 수동 일정·반복·기기 저장 기록·로컬 인덱스·저장 형식은 변경하지 않았다. 홈에서 여는 서버 기록에는 **기기에 저장된 기록 보기**를 추가해 기존 달력으로 별도 이동한다. 기존 `WorkoutCalendarPage`, `ServerRecordsDay`는 삭제하지 않았다. 서버 의존성이 없는 기존 로컬 미리보기 경로도 유지한다.

이전 운동 기록 탭의 준비 중 화면을 실제 서버 기록 화면으로 연결했다. 기존 홈/가입/분석 디자인이나 아이콘·폰트·BE·패키지 의존성은 변경하지 않았다. 새 기록 화면은 기존 관리 화면과 카드 양식을 사용한다. 달력 날짜는 원 안에 중앙 정렬하고 완료한 날만 점으로 표시한다.

- 월/날짜 로딩·빈 목록·오류는 구분한다. 조회 실패를 기록 0개로 취급하지 않는다.
- 빠른 날짜/월/필터 변경 시 이전 요청 결과를 무시한다. 더 보기의 늦은 응답도 새 필터 목록에 합쳐지지 않는다. 같은 항목만 반복되는 잘못된 페이지는 기존 목록을 보존하고 재시도를 제공한다.
- 수정 충돌/응답 불확실성 후에는 변경을 막고 서버 기록 재확인을 제공한다. 자동 덮어쓰기나 자동 수정 재전송은 하지 않는다.
- 세트 수정의 NOT_FOUND를 로그 전체 삭제로 오인하지 않는다. 로그 자체가 재조회에서 404이면 삭제되었거나 찾을 수 없다는 안내와 목록 복귀를 제공한다.
- 오류 문구와 주요 동작은 상세 하단 안전 영역에 두어 버튼이 본문 아래로 밀리지 않는다. 앱 복귀 시 상세도 재조회한다.

API는 기존 GET `/workout-logs` 및 `/{id}`, PATCH/DELETE `/{id}/sets/{set_id}`, DELETE `/{id}`를 사용한다. 전체 로그의 날짜/종목/메모를 변경하는 API는 없으므로 임의로 추가하지 않았다. 메모는 T10 종료 시 저장한 내용을 읽기 전용으로 표시한다. 휴식 입력을 비우면 기존 값을 유지하며, null로 지우는 요청도 계약에 없어 추가하지 않았다.
