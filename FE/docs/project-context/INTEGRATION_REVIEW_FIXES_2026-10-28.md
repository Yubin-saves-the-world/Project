앞선 [검토 보고서](PROJECT_REVIEW_2026-10-28.md)의 확인 사항을 수정했다. 기존 앱 아이콘·시작 화면 작업은 보존했다. 백엔드 코드·API 계약·사용자 데이터는 변경하지 않았으며 커밋·Push하지 않았다.

## 수정 내용

### 닉네임 저장 재시도

- 네트워크 오류로 저장 결과가 불확실해지면, 다음 저장 시 먼저 내 정보를 GET으로 재조회한다.
- 서버에 이미 같은 이름이 저장돼 있으면 추가 PATCH 없이 성공으로 처리한다.
- 이전 요청이 반영되지 않았으면 새 PATCH를 보낸다. GET도 실패하면 입력을 유지하고 쓰기를 진행하지 않는다.
- 닉네임 중복·입력 범위 오류의 기존 처리는 유지했다.

### 목표 체형 설명의 일관성

- 현재 `GoalPatch` 계약은 설명 생략을 ‘기존 설명 유지’로 해석하며 빈 문자열은 허용하지 않는다.
- 따라서 설명 삭제 API를 임의로 만들지 않았다. 기존 설명을 전부 비운 저장은 요청 전에 해당 입력 오류로 안내한다. 사진을 교체하는 경우에도 동일하다.
- 설명 수정, 새 사진 등록, 목표 전체 삭제·재등록은 기존 기능을 사용한다.
- 로컬 목표 저장소와 테스트 가짜 저장소도 설명 생략 시 기존 설명을 유지하도록 서버 의미에 맞췄다.
- **‘기존 설명만 삭제’ 기능은 추가하지 않았다.** 이를 지원하려면 별도의 백엔드 계약이 필요하다.

### 수동 일정에서 시작한 새 운동의 서버 저장

- 서버 모드에서는 수동 일정의 종목도 공통 `WorkoutPage`를 통해 실행한다. 이 화면의 기존 서버 로그·세트·완료·이어하기 기능을 사용한다.
- 일정에 보관된 숫자는 옛 카탈로그 인덱스다. 이 값을 서버 exercise_id로 보내지 않는다.
- 서버 종목 목록을 끝까지 조회하여 이름·부위가 정확하고 유일하게 일치하는 종목을 찾고, 시작 전 상세 ID·이름·부위·기구를 다시 확인한다. ID를 하드코딩하거나 유사 이름으로 추측하지 않는다.
- 중복 이름, 서버에서 사라진 옛 종목, 반복·누락된 페이지, 상세 정보 변경은 시작 전에 차단하고 안내한다.
- 실행 요청은 실제 서버 exercise_id를 보내며 routine_id는 생략한다. 확인한 백엔드는 이 형태를 자유 운동으로 지원한다. 수동 일정 자체를 서버의 추천 루틴으로 위장하지 않는다.
- 완료 후 홈을 다시 읽어 서버 통계와 기록을 갱신한다. 수동 일정의 종목 완료 표시도 해당 날짜의 서버 기록을 확인한다. 날짜 기록이 여러 페이지여도 끝까지 읽는다.
- 기존 기기 운동 기록·반복 일정·종목 인덱스를 수정하거나 자동 이관하지 않는다. 이전에 기기에서 시작해 진행 중이던 운동은 기존 화면에서 마무리할 수 있다.
- 로컬 미리보기는 계속 로컬로 동작한다.

### 인증 토큰 보관

- 기본 API 토큰 저장소를 `SecureTokenStore`로 변경했다. iOS Keychain과 Android 보안 저장소를 사용하는 `flutter_secure_storage` 10.3.1을 추가했다.
- 기존 SharedPreferences 토큰은 보안 저장 후 다시 읽어 확인한 다음 이전 위치에서 제거한다. 보안 저장 실패 시 옛 토큰을 먼저 삭제하지 않는다.
- 이미 보안 저장소에 새 토큰이 있으면 옛 토큰으로 덮어쓰지 않는다.
- 이전·읽기·쓰기·로그아웃을 순서대로 처리하여 동시에 시작한 요청이 빈 토큰을 읽거나 로그아웃 뒤 옛 토큰을 되살리지 않게 했다.
- 로그아웃에서는 두 저장 위치의 토큰을 정리한다. 보안 저장 실패를 일반 환경설정 저장으로 우회하지 않는다.
- iOS entitlement와 Android 백업 제외 규칙을 추가했다. Android에서는 보안 저장 파일만 백업·기기 이전에서 제외하며 다른 로컬 데이터의 백업 설정을 일괄 해제하지 않았다.

## 실제 서버를 붙일 때 남는 조건

1. 기본 `http://localhost:8080/actuator/health`는 재점검에서도 HTTP 000으로 연결되지 않았다. 현재 접근 가능한 실서버 주소가 없다. 다른 주소의 원격 서버가 꺼졌다는 의미는 아니다.
2. 최신 MVP API를 제공하는 서버 버전인지 확인해야 한다. 현재 main의 BE만 실행했다고 비교한 기능 브랜치의 API가 모두 제공되는 것은 아니다.
3. 실행 시 `USE_LOCAL_PREVIEW=false`와 기기에서 접근할 수 있는 `API_BASE_URL`을 지정해야 한다. iOS 시뮬레이터·Android 에뮬레이터·실제 휴대폰은 호스트 접근 주소가 다르다. 배포 서버는 HTTPS를 사용해야 한다.
4. 메일·DB·사진 스토리지·AI 서비스가 연결된 환경에서 가입부터 분석·운동·통계·탈퇴까지 왕복 검증이 필요하다. 테스트의 가짜 API 응답을 실제 연동 성공으로 계산하지 않았다.
5. 주간 수동 일정과 프로필 아바타는 여전히 계정별 기기 저장이다. 이번에 서버로 연결한 것은 **수동 일정에서 새로 실행하는 운동의 기록**이다. 일정·아바타의 기기 간 동기화와 옛 기기 기록 이관은 별도 계약·정책이 필요하다.
