## 이전 기준과 달라진 점

카카오 로그인 계약이 추가되어 API가 95개에서 96개로 늘었습니다. 구글·카카오 모두 2차입니다. Google ID 토큰과 Kakao 액세스 토큰을 각각 해당 API로 전달하며, 이것을 앱 서버의 로그인 토큰과 혼동하지 않습니다. 카카오가 이메일을 주지 않으면 email=null입니다.

기존에 본문이 없었던 설정·동의 API는 PATCH /api/users/me이고, 회원 탈퇴는 DELETE /api/users/me입니다. 사진 전체 삭제는 DELETE /api/photos입니다. 기존 "이후 명세 미확인" 제한은 전체본을 받은 것으로 해소됐습니다.

현재 코드의 가입 4종 필수 동의, 가입 → 로그인, 신체정보 등록 후 온보딩 완료, 로그아웃 후 로그인 이동은 최종본과 동일한 기준입니다. 실제 백엔드 인증과 전체 기능 구현 완료를 뜻하지 않습니다.

## 최종본에도 남아 있는 결정·정합성 항목

원본은 최종 기준으로 보관하되 다음 항목을 임의로 확정하거나 원본을 수정하지 않습니다.

- 기능명세 F-04의 "11MB 파일 거부"와 API의 "앱이 줄인 뒤 전송, 서버가 10MB 초과 거부"는 원본 크기/전송 크기를 구분해서 인수 테스트해야 합니다.
- ERD·API에는 회원 탈퇴 후 게시글·댓글 및 동의 이력 보관 여부가 팀 결정 필요로 남아 있습니다.
- 균형 점수·판정 산식이 검증되기 전에는 balance_score=null 및 unavailable 판정을 표시합니다.
- 확장 미션 시작 방식, 쿠폰 사용 API, 푸시 토큰 삭제 API는 명시된 API 범위와 구현 방식을 팀에서 맞춰야 합니다.
- 확장 API의 일부 길이 제한은 ERD와 다릅니다. 예: missions.title은 API 100자/ERD 50자, device_tokens.fcm_token은 API 4096자/ERD 255자. 확장 구현 전 양쪽을 맞춰야 합니다.

이전 spec-revision·team-revision-supplement는 참고용이며 최종본을 대체하지 않습니다.
