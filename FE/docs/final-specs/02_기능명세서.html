기능 명세서

무엇을 만드는지, 어떻게 쓰이는지, 어떻게 확인하는지.

앱이 무엇을 할 수 있어야 하는지를 기능 단위로 정리했습니다. 각 기능에는 화면, 사용 흐름, 규칙, 예외 상황, 끝났다고 볼 기준, 쓰는 API와 데이터가 들어 있습니다. 서버·앱·AI 담당이 같은 문서를 보고 만들고, 완료 기준으로 서로 확인합니다.
기능 25개: MVP 11(이번에 만듦) · 2차 10 · 확장 4. 담당은 역할 이름(BE-1 등)이고, 사람 배정은 팀이 정합니다.

F-01

회원가입

MVP필수서버 BE-1 · 앱 APP-B

이메일, 비밀번호, 닉네임과 동의 4가지로 계정을 만든다.

처음 앱을 연 사람이 이메일로 가입하고 바로 로그인할 수 있다.

화면

  • 가입 (STEP 01)

사용 흐름

  1. 이메일·비밀번호·닉네임을 입력한다
  2. 이용약관·개인정보·신체 사진·AI 처리 동의 4개를 체크한다
  3. 가입 버튼을 누르면 가입 요청을 보낸다
  4. 성공하면 같은 이메일·비밀번호로 로그인 요청을 이어서 보낸다
  5. 로그인에 성공하면 신체정보 입력 화면으로 간다

꼭 지켜야 할 규칙

  • 비밀번호는 8~64자, 영문과 숫자를 각각 1자 이상 포함한다
  • 닉네임은 2~20자이고 다른 사람과 겹치면 안 된다
  • 이메일은 소문자로 바꿔 저장하고 비교한다
  • 동의 4개가 모두 체크되어야 가입된다. 사진·AI 동의는 한 체크박스로 묶어 보여줘도 된다
  • 가입만으로는 토큰을 주지 않는다(앱이 이어서 로그인한다)
  • 동의는 종류별로 약관 버전과 시각을 이력으로 남긴다

예외 상황과 처리

상황화면·동작
이미 가입된 이메일이메일 칸에 오류 표시 (EMAIL_DUPLICATED)
닉네임이 겹침닉네임 칸에 오류 표시 (NICKNAME_DUPLICATED)
동의가 빠짐빠진 체크를 강조 (TERMS_REQUIRED)
입력 형식 오류오류가 난 칸마다 사유 표시 (VALIDATION_FAILED의 fields)

완료 기준 (이게 되면 끝)

  • 올바른 값으로 가입하면 서버 DB에 회원 1행과 동의 4행이 생긴다
  • 같은 이메일로 다시 가입하면 이메일 칸 오류가 나온다
  • 동의를 하나라도 빼면 가입되지 않는다
  • 가입 직후 로그인해 신체정보 화면으로 이동한다

F-02

로그인 · 자동 로그인 · 로그아웃

MVP필수서버 BE-1 · 앱 APP-B

이메일로 로그인하고, 앱을 다시 열어도 로그인이 유지된다.

한 번 로그인하면 7일 동안은 다시 입력하지 않아도 된다.

화면

  • 로그인
  • 스플래시(앱 시작)
  • 설정(로그아웃)

사용 흐름

  1. 앱을 켜면 저장된 토큰이 있는지 본다
  2. 토큰이 없으면 로그인 화면, 있으면 내 정보를 조회한다
  3. 내 정보의 동의·신체정보 상태에 따라 동의 화면, 신체정보 화면, 홈 중 하나로 간다
  4. 로그아웃하면 앱이 토큰을 지우고 로그인 화면으로 간다

꼭 지켜야 할 규칙

  • 토큰 유효 기간은 7일이고 재발급 API는 없다. 만료되면 다시 로그인한다
  • 이메일이 없는 경우와 비밀번호가 틀린 경우를 구분해 알려주지 않는다
  • 탈퇴한 회원은 토큰이 남아 있어도 모든 요청이 UNAUTHORIZED
  • 로그아웃은 서버가 하는 일이 없다(앱의 토큰 삭제가 전부)

예외 상황과 처리

상황화면·동작
이메일·비밀번호가 틀림"이메일 또는 비밀번호" 문구 표시, 입력은 유지 (INVALID_CREDENTIALS)
토큰 만료·탈퇴토큰 삭제 후 로그인 화면 (UNAUTHORIZED)

완료 기준 (이게 되면 끝)

  • 로그인 후 앱을 완전히 종료했다 켜도 홈(또는 신체정보)으로 바로 간다
  • 7일이 지났거나 탈퇴한 계정이면 로그인 화면으로 돌아간다
  • 로그아웃하면 다시 앱을 열어도 로그인 화면이다

쓰는 API 3개

POST/api/auth/login이메일 로그인— 로그인 버튼을 눌렀을 때
POST/api/auth/logout로그아웃— 로그아웃을 눌렀을 때
GET/api/users/me내 정보 조회— 앱 시작 때, 로그인 직후, 설정 화면에서

F-03

신체정보 · 설문

MVP필수서버 BE-1 · 앱 APP-A

키, 몸무게, 나이, 운동 목적·횟수·경력을 입력한다. 값이 바뀌면 이력으로 쌓인다.

내 정보를 한 번 입력하면 분석과 루틴이 나에게 맞게 만들어진다.

화면

  • 신체정보 입력 (STEP 02)
  • 프로필 수정

사용 흐름

  1. 키, 몸무게, 나이를 입력한다
  2. 운동 목적(근육·체중 감량·자세 교정)을 고른다
  3. 일주일에 운동할 수 있는 횟수와 운동 경력을 고른다
  4. 저장하면 온보딩이 끝나고 다른 기능을 쓸 수 있다

꼭 지켜야 할 규칙

  • 키 100~250cm, 몸무게 30~250kg(소수 첫째 자리), 나이 10~100, 주 1~7회
  • 운동 경력: 3개월 미만 / 1년 미만 / 1년 이상
  • 최초 등록에 성공하면 온보딩 완료로 본다(별도 값이 아니라 신체정보가 있는지로 판단)
  • 수정은 덮어쓰지 않고 새 이력 행으로 저장한다(체중 변화 기록)
  • 목적·횟수·경력 중 하나라도 바뀌면 "루틴을 다시 만드는 것을 권장"을 알려준다
  • 성별 입력 화면이 없으면 보내지 않아도 된다(none으로 저장)

예외 상황과 처리

상황화면·동작
이미 등록함등록 대신 수정으로 보낸다 (PROFILE_ALREADY_EXISTS)
범위 밖 값해당 칸에 오류 (VALIDATION_FAILED)

완료 기준 (이게 되면 끝)

  • 처음 저장하면 이후 GET /users/me의 온보딩 완료가 true
  • 수정하면 이력이 한 행 늘고 조회는 가장 최근 값을 돌려준다
  • 목적을 바꾸면 응답에 루틴 재생성 권장이 true

쓰는 API 3개

POST/api/users/me/profile신체정보 등록— 신체정보를 처음 저장할 때
GET/api/users/me/profile신체정보 조회— 프로필 화면을 열 때
PATCH/api/users/me/profile신체정보 수정— 값을 고쳐 저장할 때

F-04

사진 촬영 · 업로드

MVP필수서버 BE-2 · 앱 APP-A

정면(필수)·측면(선택) 사진을 찍어 올린다. 지울 수도 있다.

가이드 선에 맞춰 찍은 사진으로 분석을 받을 수 있다.

화면

  • 사진 촬영 안내
  • 촬영·앨범 선택
  • 내 사진 관리

사용 흐름

  1. 촬영 가이드(전신, 밝은 곳, 몸에 붙는 옷)를 보여준다
  2. 정면 사진을 찍거나 앨범에서 고른다
  3. 측면 사진은 선택이다
  4. 앱이 사진을 줄여서(긴 변 1024px, JPG) 올린다
  5. 올라간 사진의 번호(photo_id)를 분석 요청에 쓴다

꼭 지켜야 할 규칙

  • JPG·PNG, 10MB 이하. 파일 내용으로 형식을 판별한다
  • 앱이 올리기 전에 촬영 방향(EXIF 회전)을 반영하고 긴 변을 1024px 이하로 줄인다
  • 사용자당 사진 최대 20장
  • 사진은 비공개 저장소에 두고, 화면에 보여줄 주소는 1시간짜리 서명 URL이다(저장하지 말고 다시 조회)
  • 목표 사진(type=goal)은 임시 파일이다. 올린 뒤 1시간 안에 목표로 등록하지 않으면 서버가 지운다
  • 사진 동의(body_photo)를 철회한 사용자는 올릴 수 없다

예외 상황과 처리

상황화면·동작
파일이 너무 큼줄여서 다시 올린다 (IMAGE_TOO_LARGE)
JPG·PNG가 아님다른 사진을 고르게 안내 (IMAGE_INVALID_TYPE)
20장을 넘음사진 정리 화면으로 (PHOTO_LIMIT_EXCEEDED)
사진 동의 철회 상태설정의 동의 화면으로 (CONSENT_REQUIRED)
분석 중인 목표 사진을 삭제삭제 불가 안내 (PHOTO_IN_USE)

완료 기준 (이게 되면 끝)

  • 정상 사진은 201과 함께 photo_id·서명 URL이 온다
  • 11MB 파일은 거부된다
  • 사진을 지우면 저장소에서도 지워지고 이미 끝난 분석 결과는 남는다
  • 목표 사진을 올리고 1시간 안에 등록하지 않으면 목록에서 사라진다

쓰는 API 4개

POST/api/photos사진 업로드— 사진을 올릴 때
GET/api/photos사진 목록— 내 사진 목록을 볼 때
DELETE/api/photos/{photo_id}사진 삭제— 사진 하나를 지울 때
DELETE/api/photos사진 전체 삭제— 사진을 한꺼번에 지울 때

F-05

체형 분석 (사진)

MVP필수서버 BE-2 · AI · 앱 APP-A

사진에서 어깨·골반 기울기 등을 계산하고, 목표가 있으면 AI가 비교 소견을 더한다.

사진을 올리면 몇 초 안에 내 몸의 상태를 수치와 쉬운 설명으로 볼 수 있다.

화면

  • 분석 중
  • 분석 결과
  • 분석 기록

사용 흐름

  1. 정면 사진(과 측면 사진, 목표)을 골라 분석을 요청한다
  2. 서버가 바로 "접수"만 답한다(202)
  3. 앱이 2초마다 결과를 물어본다(최대 60초)
  4. 끝나면 수치·판정·AI 소견을 보여준다. 실패하면 이유와 함께 재촬영을 안내한다

꼭 지켜야 할 규칙

  • 비동기: 접수 즉시 202, 앱은 2초마다 최대 60초 조회. 서버는 90초가 지난 처리를 실패(AI_TIMEOUT)로 바꾼다
  • 사용자당 처리 중(pending) 분석은 1건. 하루 3회 한도(제안, 사진 품질 실패는 세지 않음)
  • 사진에 없는 값은 만들지 않는다. 측면 사진이 없으면 목 기울기는 "측정 불가"(null)
  • 판정 기준·점수 산식이 검증되기 전에는 balance_score가 null이고 판정은 "평가 불가"
  • 수치(MediaPipe)와 AI 소견(Qwen-VL)을 구분해서 보여준다. AI 소견은 목표가 있을 때만
  • failed는 HTTP 오류가 아니라 200으로 오고 error_code로 이유를 알려준다

운동 실행 · 세트 기록 · 타이머

MVP필수서버 BE-2 · 앱 APP-B

종목 하나를 시작하고, 세트마다 무게와 횟수를 기록하고, 끝낸다.

운동하면서 세트를 바로 적고, 앱을 나갔다 와도 이어서 할 수 있다.

화면

  • 운동 실행
  • 휴식 타이머
  • 운동 완료

사용 흐름

  1. 루틴의 종목(또는 자유 운동 종목)을 눌러 시작한다
  2. 세트를 마칠 때마다 무게·횟수를 저장한다(세트마다 앱이 번호표 client_set_id를 만든다)
  3. 세트 사이에 휴식 타이머를 센다
  4. 종목을 끝내면 소요 시간, 총 볼륨, 루틴 진행률을 보여준다

꼭 지켜야 할 규칙

  • 종목 하나 = 운동 기록 하나. 4종목 루틴이면 4번 시작한다
  • 시작 시각은 서버가 기록한다. 앱을 나갔다 오면 "지금 − 시작 시각"으로 경과 시간을 복구한다
  • 같은 종목이 진행 중이면 새로 만들지 않고 그 기록을 돌려준다(이어하기)
  • 진행 중인 기록이 6시간을 넘으면 서버가 "자동 중단"으로 바꾸고 통계에서 뺀다
  • 같은 client_set_id로 다시 보내도 세트가 두 번 만들어지지 않는다. 응답을 못 받았으면 같은 값으로 다시 보낸다
  • 세트를 고칠 때는 마지막으로 받은 version을 같이 보낸다. 다르면 충돌
  • 완료한 세트가 0개면 종료할 수 없다(기록을 지운다)
  • 총 볼륨은 저장하지 않고 조회 때 무게 × 횟수의 합으로 계산한다

예외 상황과 처리

상황화면·동작

세트 번호 중복기록을 다시 조회해 번호를 다시 정한다 (SET_DUPLICATED)
이미 끝난 기록에 세트 추가기록 상세로 (WORKOUT_ALREADY_COMPLETED)

완료 기준 (이게 되면 끝)

  • 운동을 시작하면 201, 같은 종목으로 다시 시작하면 200(resumed=true)
  • 같은 세트를 두 번 보내도 DB에 한 행만 있다
  • 앱을 끄고 다시 켜면 이어하기가 되고 경과 시간이 맞다
  • 종료하면 루틴의 모든 종목이 끝났을 때 루틴 상태가 done이 된다
