# 설정(마이페이지) 화면 스펙 (앱 팀 전달용)

설계 이미지: `settings_board.png` (개별 화면 `1_settings.png` ~ `9_consent.png`, 생성 코드는 `build.py`)

## 1. 한눈에

- 화면은 **메인 1개 + 하위 3개**(프로필 수정, 사진 데이터 관리, 동의 관리)이고, 안내 창은 3종(로그아웃, 회원 탈퇴, AI 동의 끄기)입니다.
- 메인 화면은 섹션 4개입니다: 프로필 카드 / MY BODY / NOTIFICATIONS / ACCOUNT.
- 화면보다 길어서 **스크롤**이 필요합니다. 맨 위에 고정하는 것은 없고, 전체가 한 번에 스크롤됩니다.
- 로그인한 사용자만 들어옵니다. 신체정보를 입력하지 않은 사용자는 이 화면에 오기 전에 신체정보 화면으로 보냅니다.

## 3. 화면 구성과 데이터 연결

### 3-1. 프로필 카드
| 표시 | 값 | API |
|---|---|---|
| 아바타 글자 | 닉네임 첫 글자 | `GET /users/me` → `nickname` |
| 이름 | 닉네임 | 같음 |
| 이메일 | 이메일 (카카오 가입자는 null일 수 있음, 그땐 줄 숨김) | `email` |
| `프로필 수정` 버튼 | 프로필 수정 화면으로 이동 | |

프로필 사진 업로드 기능은 서버에 없습니다. 아바타는 글자로만 씁니다.

### 3-2. MY BODY
| 행 | 값 표시 | 값의 출처 | 누르면 |
|---|---|---|---|
| 신체 정보 | `174cm · 68kg · 18세` | `GET /users/me/profile` → `height_cm`, `weight_kg`, `age` | 신체정보 수정 화면(기존 `profile_form_page`) |
| 운동 목적 | `근육 키우기` / `체중 감량` / `자세 교정` | `goal_type` = `muscle` / `diet` / `posture` | 같은 화면 |
| 주 운동 횟수 | `주 3회` | `weekly_frequency` | 같은 화면 |
| 운동 경력 | `3개월 미만` / `1년 미만` / `1년 이상` | `experience_level` = `under3m` / `under1y` / `over1y` | 같은 화면 |
| 목표 체형 | `설정 안 함` / `분석 중` / `설정됨` / `다시 설정` | `GET /goal-bodies` → `status` (없음=404 `GOAL_NOT_FOUND`, `pending`, `done`, `failed`) | 목표 체형 화면 |
| 분석 기록 | `N회` | `GET /body-analyses` → `total` | 분석 기록 목록 |

- 신체정보를 수정하고 응답의 `routine_refresh_recommended=true`이면 "맞춤 루틴을 새로 만들까요?"를 띄웁니다.
- 목표 체형 **사진은 서버가 분석 직후 삭제**하므로 사진 미리보기·"사진 변경" 문구를 쓰지 않고 상태만 보여 줍니다.

### 3-3. NOTIFICATIONS
| 행 | 값 | API |
|---|---|---|
| 운동 알림 | 스위치 + 보조글 `매일 18:00` | `GET/PATCH /notification-settings`, type=`workout` |
| 식단 알림 | 스위치 + 보조글 `매일 12:00` | type=`diet` |

- `PATCH /notification-settings/{type}` 본문은 `{enabled?, time?(HH:mm)}`입니다. 둘 중 하나는 보내야 합니다.
- 행(스위치 이외 영역)을 누르면 시각 선택. 스위치를 끄면 시각은 유지하고 보조글을 `꺼짐`으로 표시합니다.
- `streak_risk`(연속 기록 끊김) 알림은 시각을 바꿀 수 없어서(서버 고정) 이 화면에 넣지 않았습니다. 필요하면 3번째 행으로 추가하고 시각 선택 없이 스위치만 둡니다.
- 이 API는 **확장 단계**입니다. 알림 기능이 붙기 전에는 NOTIFICATIONS 섹션을 통째로 숨깁니다.
- 푸시 기기 토큰은 앱 실행 시 `PUT /users/me/device-token`으로 따로 등록합니다.

### 3-4. ACCOUNT
| 행 | 보조글 | 누르면 |
|---|---|---|
| 사진 데이터 관리 | `올린 사진 N장 · 직접 삭제할 수 있어요` (`GET /photos?type=current` → `total`) | 사진 데이터 관리 화면 |
| 동의 관리 | `사진 · AI 분석 동의` | 동의 관리 화면 |
| 개인정보 처리방침 | | 웹뷰 또는 외부 링크 |
| 로그아웃 | | 안내 창 → 앱이 토큰 삭제 → 로그인 화면 (서버 호출 `POST /auth/logout`은 선택, 응답 204) |
| 회원 탈퇴 (빨강) | | 안내 창 → `DELETE /users/me` |

맨 아래 `VERSION 1.0.0`은 앱 버전(`package_info`)을 씁니다.

## 4. 하위 화면

### 4-1. 프로필 수정 (`7_profile.png`)
- 닉네임 입력(2~20자) + 오른쪽 위 글자 수 `5 / 20`. 이메일은 읽기 전용(자물쇠 아이콘, 회색 배경).
- `PATCH /users/me` `{nickname}`. 자기 현재 닉네임을 그대로 저장하면 성공으로 처리됩니다.
- 오류: `NICKNAME_DUPLICATED`(409) → 칸 빨간 테두리 + `이미 사용 중인 닉네임이에요.` / `VALIDATION_FAILED` → 길이 안내.
- 저장 성공 → 이전 화면으로 돌아가고 닉네임 즉시 반영. 값이 바뀌지 않았으면 버튼 비활성.

### 4-2. 사진 데이터 관리 (`8_photos.png`)
- 위 카드: `올린 사진 N / 20장` + 빨간 `전체 삭제`.
- 3열 격자(3:4 비율). 각 사진 왼쪽 아래에 `정면`/`측면` 태그, 오른쪽 위 `×` 버튼. 20장 미만이면 마지막 칸에 `+ 추가`.
- API: `GET /photos?type=current`(이미지 `url`은 1시간짜리 서명 주소, 목록을 다시 받으면 새로 발급), `DELETE /photos/{photo_id}`, `DELETE /photos?type=current`.
- 삭제해도 **분석 결과는 남고 사진만 지워진다**는 안내 문구를 아래에 둡니다.
- 삭제 전 확인 창을 한 번 띄웁니다. `PHOTO_IN_USE`(409)는 처리 중인 목표 체형 사진일 때만 나옵니다. "처리가 끝나면 지울 수 있어요".

### 4-3. 동의 관리 (`9_consent.png`)
- REQUIRED: 서비스 이용약관, 개인정보 처리방침. 스위치는 켜진 채 **잠금(투명도 45%)**. "필수 동의는 회원 탈퇴로만 철회할 수 있어요."
- OPTIONAL USE: 체형 사진 사용(`body_photo_agreed`), AI 분석(`ai_processing_agreed`). `GET /users/me`로 읽고 `PATCH /users/me`로 바꿉니다.
- 끌 때 안내 창을 띄웁니다. 켤 때는 안내 창 없이 바로 `true`로 보냅니다.
  - AI 분석 끄기: `진행 중인 분석이 있으면 취소돼요. 새 분석과 AI 코치는 다시 동의해야 쓸 수 있어요. 이미 만든 결과는 계속 볼 수 있어요.`
  - 체형 사진 끄기: `새 사진을 올릴 수 없어요. 이미 올린 사진은 사진 데이터 관리에서 직접 지울 수 있어요.`

## 5. 안내 창

| 창 | 제목 / 본문 | 버튼 |
|---|---|---|
| 로그아웃 (`5_logout.png`) | `로그아웃할까요?` / 다시 로그인하면 기록은 그대로 남아 있어요. | `취소`(테두리) · `로그아웃`(파랑) |
| 회원 탈퇴 (`6_withdraw.png`) | `정말 탈퇴할까요?` / 탈퇴하면 바로 로그아웃되고, 아래 정보가 모두 삭제돼요. 같은 이메일로 다시 가입할 수 있어요. + 삭제 목록 4줄 + 확인 체크 | `취소` · `탈퇴하기`(빨강) |
| AI 동의 끄기 (`9_consent.png`) | `AI 분석을 끌까요?` | `취소` · `끄기` |

- 폭은 화면 좌우 32 여백, 둥글기 24, 배경 어둡게 45%. 바깥을 눌러도 닫히지 않게 합니다(탈퇴·로그아웃).
- **회원 탈퇴 창은 확인 체크박스를 켜야 `탈퇴하기`가 활성**입니다(꺼져 있으면 빨강 40% 투명도). 되돌릴 수 없는 동작이기 때문입니다.
- 탈퇴 성공(`204`) → 토큰과 로컬 데이터를 모두 지우고 로그인 화면으로.
- 로그아웃은 서버가 아무 처리도 하지 않으므로 앱이 토큰만 지우면 끝입니다.

## 7. 깨지지 않게 하는 규칙 (중요)

기본 이미지만 맞춰서 만들면 긴 글자·작은 화면·큰 글씨에서 깨집니다. 아래를 지키면 `2_stress.png`(폭 320, 글씨 130%, 20자 닉네임)처럼 유지됩니다.

1. **행 높이를 고정하지 않습니다.** `ConstrainedBox(minHeight: 56)` + `Padding`. 글이 길면 행이 늘어납니다.
2. **행 안은 `Row` + `Expanded`(제목) + `Flexible`(값)** 으로 짭니다. 값은 `maxWidth`를 행의 58%로 제한하고, **줄바꿈을 허용**(`softWrap: true`)합니다. 값을 말줄임으로 잘라 버리면 `174.5cm · 68.5kg · 18세` 같은 핵심 정보가 사라집니다.
3. **닉네임·이메일만 한 줄 말줄임**(`maxLines: 1, overflow: TextOverflow.ellipsis`). 이때 `Expanded`/`Flexible`로 감싸야 오른쪽 버튼을 밀어내지 않습니다.
4. **프로필 카드는 `Wrap`** 으로 만들어, 공간이 모자라면 `프로필 수정` 버튼이 아래 줄로 내려가게 합니다(`2_stress.png`).
5. **구분선은 카드 폭 전체.** 행 사이에 `Divider(height: 1)`를 넣고, 카드에 `clipBehavior: Clip.antiAlias`를 줘서 둥근 모서리 밖으로 삐져나오지 않게 합니다. 구분선을 안쪽으로 들여 쓰면 오른쪽에서 끊겨 보입니다.
6. **전체를 `SingleChildScrollView`(또는 `ListView`) + `SafeArea`** 로 감쌉니다. 아래 홈 인디케이터 영역을 위해 맨 아래 여백 44 이상.
7. **글씨 크기는 시스템 설정을 따릅니다.** `textScaler`를 고정하지 마세요. 130%에서도 깨지지 않게 위 1~4를 지킵니다.
8. 스위치 행은 **스위치 자리를 52폭으로 고정**하고(`SizedBox`), 보조글은 줄바꿈 허용. 보조글이 길어도 스위치가 밀려 나가지 않습니다.
9. 안내 창은 `Dialog(insetPadding: EdgeInsets.symmetric(horizontal: 32))` + 내용 `SingleChildScrollView`. 작은 기기·큰 글씨에서 내용이 길면 창 안에서 스크롤되게 합니다.
10. 사진 격자는 `GridView(crossAxisCount: 3)` + `childAspectRatio: 3/4`. 개수가 많아도 행이 늘어나는 방식이라 깨지지 않습니다.

## 8. 서버에 없어서 넣지 않은 것

- **비밀번호 변경**(로그인 상태에서): API가 없습니다. 필요하면 서버부터 추가해야 합니다. 지금은 로그인 화면의 `비밀번호 찾기`만 있습니다.
- **프로필 사진 업로드**: API가 없습니다.
- **이메일 변경**: API가 없어서 읽기 전용으로 뒀습니다.

## 9. 결정이 필요한 것

- **회원 탈퇴 때 작성한 글·댓글**: 지금 서버는 **함께 삭제**합니다. 탈퇴 창의 삭제 목록에 `작성한 글과 댓글`이 들어간 이유입니다. "탈퇴한 사용자"로 표시하고 남기려면 서버를 바꿔야 하고, 그러면 이 문구도 바꿉니다.
- **개인정보 처리방침 링크 주소**: 아직 없습니다.
- **NOTIFICATIONS 섹션**: 알림 기능이 확장 단계라서 MVP 출시 때는 숨깁니다.

## 10. 디자인 파일 다시 만들기

```bash
cd design/settings
python3 build.py
```

Chrome으로 렌더링하며, 이때 **글자가 칸을 넘치거나 화면 밖으로 나가거나 잘리는지 자동으로 검사**해서 결과를 출력합니다. 값이나 문구를 바꾼 뒤 다시 돌려서 `전체 통과`가 나오는지 확인하세요.
