# ERD 반영 항목과 인수 시나리오

수정 ERD가 제공되지 않아 실제 컬럼의 존재 여부를 확인한 문서는 아니다. 기존 스키마에 대응 항목이 있으면 중복 생성하지 말고 이름을 매핑한다. 아래 제약과 상태 불변 조건을 만족하도록 반영한다. 마이그레이션 SQL·앱·서버 코드는 포함하지 않는다.

범용 jobs 시스템 대신 목표·분석의 도메인 상태를 유지한다. 외부 파일 삭제에 필요한 cleanup_tasks는 재시도할 객체 키를 계정 삭제 이후에도 잃지 않기 위한 최소 영속 기록이다. 기존 작업 인프라가 같은 보장을 하면 재사용한다.

사용자당 진행 중 운동은 사용자행 잠금 후 조회·생성하거나 유일한 활성 슬롯을 두어 보장한다. “조회 후 insert”만 수행하면 동시 요청에 두 로그가 생길 수 있다. 상태 종료·6시간 만료 때 슬롯도 같은 트랜잭션에서 해제한다. MySQL에 부분 유일 인덱스가 있다고 가정하지 않는다.

completed 로그 집계는 공통 조회식을 공유한다. 루틴 진행률을 캐시한다면 세트·로그 변경과 같은 트랜잭션에서 갱신한다. 조회 때 직접 계산해도 동일 조건을 사용한다. 운동명·종목 삭제에 대비해 기록 스냅샷을 보존한다. 관리자가 사용 중 종목을 비활성화해도 기존 기록·잠긴 루틴은 손상시키지 않는다.

## 2. 삭제와 외래키 정책

- 목표·사진 삭제: 완료 분석의 FK는 nullable/SET NULL, 결과·입력 설명 스냅샷은 유지. pending 분석이 필요한 사진 삭제 시 INPUT_PHOTO_DELETED로 실패 처리하고 결과 반영을 차단한다.
- 루틴 교체: 미시작·미완료·미건너뛰기 날짜만 교체. 로그가 연결된 아이템은 삭제하지 않는다. 로그의 routine_id를 다른 루틴으로 옮기지 않는다.
- 운동 기록 삭제: 세트 삭제·통계/루틴 재계산은 함께 처리. routine.execution_locked는 유지한다. 지급 완료한 미션 근거는 삭제된 로그의 개인 상세를 남기는 대신 지급 사건과 인정일을 최소한으로 보존한다.
- 탈퇴 제안: 게시글·댓글은 즉시 비공개 처리하고 본문·사진·작성자 개인정보를 정리한다. 공개된 작성자 자리에는 탈퇴한 사용자만 표시한다. 대댓글 관계 유지용 tombstone은 허용하되 원문 본문은 노출하지 않는다. 익명화해 본문을 계속 공개할지에 대한 원문의 미결정은 이 기본안으로 대체한다.
- 탈퇴 정리: 신체정보·사진·분석·목표·운동·대화·푸시 토큰·개인 캐시를 삭제한다. 정리 작업 등록과 계정 차단이 먼저 원자적으로 완료돼야 한다. 제휴 보상·운영 감사 이력 등 별도 보관이 필요한 기록은 실제 보관 정책이 확정된 최소 항목만 보관하며 기간을 임의로 정하지 않는다.
- 사용자 식별은 재가입 이메일이 아니라 내부 user_id를 사용한다. 이전 cleanup_tasks가 같은 이메일로 새 가입한 계정의 데이터를 삭제하지 않아야 한다.
- 삭제 실패는 작업을 보존하고 재시도한다. 서명 URL은 발급 후 만료 전까지 유효할 수 있으므로 물리 파일 삭제와 새 URL 발급 금지가 함께 필요하다.

## 4. 이번 산출물의 검토 항목

- 기존 분석의 6개 MVP 문제와 후속 기능 5개 공백을 기능·API·데이터에 연결했다.
- API 예시의 상태·시간·nullable 조건·요청 반영 값·버전·주간 날짜 개수를 맞췄다.
- 신규 확장 API 1개와 관리자 API 2개 단계 이동을 범위 표에 반영했다.
- 실측 판정·처방 데이터·제휴 계약을 검증 완료 사실로 적지 않았다.
- 실제 코드·공유 원문·기존 v1.1 문서는 수정하지 않았다.
