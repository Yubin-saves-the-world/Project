API 명세서

전체 95개. 기능별로 묶고, 보내는 값·받는 값·실패했을 때를 한 곳에 모았습니다.

앱과 서버가 주고받는 요청과 응답입니다. 기능 순서로 묶었고, MVP 35개는 처음부터 펼쳐져 있습니다. 2차 34개 · 확장 26개는 눌러서 펼칩니다. 어떤 기능이 왜 필요한지는 기능 명세서에 있습니다.

먼저 알아둘 것

주소모든 경로는 /api로 시작합니다. 개발 중 주소는 http://localhost:8080, Android 에뮬레이터에서는 http://10.0.2.2:8080
형식JSON(UTF-8), 필드 이름은 snake_case. 사진과 게시글 이미지만 multipart/form-data
로그인헤더에 Authorization: Bearer {access_token}. 토큰은 7일이고 재발급은 없습니다. 만료되면 401 → 다시 로그인
받는 값필드는 항상 있습니다. 값이 없으면 null, 목록은 []. 목록은 { items, page, page_size, total }
시간날짜 2026-10-06, 시각 2026-10-06T19:02:10+09:00(한국 시간). 한 주는 월요일부터
실패{ code, message, status, fields }. 앱은 code로 나누고 message는 그대로 보여줘도 됩니다
모든 API 공통 실패400 VALIDATION_FAILED(입력 오류, fields에 칸별 사유) · 401 UNAUTHORIZED(토큰 없음·만료·탈퇴) · 403 FORBIDDEN(관리자 전용) · 403 ONBOARDING_REQUIRED(신체정보 등록 전)
내 것이 아닌 데이터404 NOT_FOUND (남의 데이터가 있는지도 알려주지 않습니다)
분석은 기다리는 방식요청하면 바로 202로 접수하고, 앱이 GET /body-analyses/{id}를 2초마다 최대 60초 조회합니다. 분석 실패(failed)도 HTTP 200입니다

처음부터 끝까지 부르는 순서

① POST  /api/users                    가입 (토큰은 오지 않음)
② POST  /api/auth/login              로그인 → access_token
③ POST  /api/users/me/profile        신체정보 → 온보딩 끝
④ POST  /api/photos                  사진 올리기 → photo_id
⑤ POST  /api/goal-bodies             (선택) 목표 체형
⑥ POST  /api/body-analyses/photo     분석 요청 → 202, analysis_id
⑦ GET   /api/body-analyses/{id}      2초마다 확인 (pending → done / failed)
⑧ POST  /api/routines                { analysis_id } → 오늘부터 7일 루틴
⑨ GET   /api/routines/today          홈의 오늘의 루틴
⑩ POST  /api/workout-logs            운동 시작 (종목 1개)
⑪ POST  /api/workout-logs/{id}/sets  세트마다 기록 (client_set_id)
⑫ PATCH /api/workout-logs/{id}/complete  운동 종료

표의 *는 꼭 보내야 하는 값, null 가능은 값이 없을 수 있다는 뜻입니다. 예시의 값은 모양을 보여주는 용도입니다.
