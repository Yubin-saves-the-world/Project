# 팀장 API 명세 기준 · 2026-10-06

사용자가 이 명세서로 통일하라고 지정했다. 요청·응답·필수 동의·기능 단계·서버 상태는 이 문서를 우선한다. 화면 색상·간격·배치는 피그마를 기준으로 한다. 이전 spec-revision과 team-revision-supplement는 참고용 제안이며 이 기준과 충돌하면 적용하지 않는다.

## 받은 원본의 범위

[전달받은 원본](team-api.received.html)을 그대로 보관했다. HTML은 앱 UI가 아니라 API 명세를 읽기 위한 문서다. 실행하거나 완전한 문서처럼 복구하지 않았다.

원본에 전체 95개라고 적혀 있지만 실제 파일은 `F-04 / DELETE /api/photos/{photo_id}` 설명 끝부분의 `... (353KB 남음)`에서 잘렸다. 완전한 operation 9개와 일부 operation 1개만 전달되었다. F-05 이후는 목차·상단 흐름 외에는 본문이 없다. 특히 구글 F-12, 설정·동의·탈퇴 F-11의 요청/응답은 확인되지 않았다. 기존 문서로 부족한 내용을 메워 확정하지 않는다.

## 통일한 기준

- JSON snake_case, 모든 경로 `/api`, 성공 응답의 최상위 wrapper를 추가하지 않는다.
- 목록 `{items, page, page_size, total}`, 값 없음 null, 빈 목록 [].
- 공통 오류 `{code, message, status, fields}`, 입력 오류 400, 인증 없음·만료 401, 동의 부족·온보딩 미완료 등의 오류는 서버 code로 구분한다.
- 가입은 `POST /api/users` 201이며 토큰을 받지 않는다. 이어서 `POST /api/auth/login`, 토큰을 저장한 뒤 `GET /api/users/me`로 다음 화면을 결정한다.
- 약관·개인정보·사진·AI 처리 동의 4개 모두 true 필수. policy_version은 선택이며 생략하면 서버 현재 버전을 사용한다. 임의의 preview-v1을 서버로 보내지 않는다.
- 로그인 password는 1~64자, 가입 password는 8~64자·영문과 숫자 포함. 가입 규칙을 로그인에 적용하지 않는다.
- `consent_completed=false` → 동의, `onboarding_completed=false` → 신체정보, 나머지 홈. 신체정보 최초 등록이 온보딩 완료이며 사진 분석은 별개다.
- 신체정보 최초 등록 POST, 이후 수정 PATCH. 수치 범위·enum은 전달받은 명세와 동일하다.
- JWT 7일, refresh 없음. 서버 연결 시 안전한 토큰 저장소 사용, 만료 시 로그인. 현재 로컬 미리보기는 JWT를 생성하거나 저장하지 않는다.
- 로그아웃은 서버 계정 삭제가 아니다. 로컬 세션과 메모리 입력만 정리하고 로그인 화면으로 이동한다. 가입 데이터·사진·기록은 유지한다. 서버 연결 시 토큰·개인정보 캐시는 정리하되 서버 기록은 보존한다.
- 사진은 JPEG/PNG, EXIF 회전 적용, 긴 변 1024px 이하로 축소 후 JPEG 전송, 전송 파일 10MB 이하. 기기 파일 path는 서버 photo_id가 아니다.
- 사진 20장 제한, URL 1시간 서명 URL, 새 조회 후 만료 URL 교체. 목표 사진 임시 보관 정책은 서버에서 처리한다.
- 구글은 목차상 2차, 글 분석은 2차. 카카오는 받은 문서에서 확인되지 않는다. MVP 구현에 임의의 소셜 인증 API를 추가하지 않는다.

## 현재 코드 반영

`ApiContract`에 확인된 경로·시간·사진 제한, `ApiFailure`에 오류 형식, `AuthSession`·`CurrentUser`에 서버 응답과 초기 화면 분기 계약을 정의했다. 백엔드 HTTP 호출은 아직 연결하지 않았다.

가입 ViewModel은 register → login 순서로 호출한다. 가입 성공 후 로그인만 실패하면 가입 POST를 반복하지 않고 로그인부터 재시도한다. 가입 후 이전 단계로 돌아간 화면에서는 등록된 필드를 수정하거나 가입 POST를 다시 호출하지 않는다.

3페이지 흐름에서 신체정보 등록 직후 `onboardingCompleted=true`다. 3번째 페이지는 선택적인 분석 준비 화면이며 온보딩 완료와 별개다. 신체정보가 저장된 상태로 재실행하면 홈으로 진입한다. `completed`는 이 미리보기의 분석 준비 화면을 닫았는지 나타내며 로컬 JSON은 `analysis_setup_completed`로 명확히 구분한다.

로그아웃 후 로그인 페이지를 추가했다. **LocalOnboardingRepository의 로그인은 저장된 이메일과 입력 형식으로 화면 전환만 확인하는 개발용 기능**이며 비밀번호를 검증하지 않는다. 화면에 이 제한을 명시한다. 비밀번호는 디스크에 보관하지 않는다. 프로덕션에서 이 저장소를 사용하지 않고 실제 인증 저장소로 교체한다.

이전 버전의 로컬 JSON은 분석 준비 완료 플래그를 읽을 수 있게 유지한다. 이전 사진/AI 미동의 데이터는 동의를 자동으로 true로 바꾸지 않는다. 기존 미동의 데이터는 홈보다 동의 화면을 먼저 표시하고 사용자가 4개를 확인한 뒤 개발용 저장소에 반영한다. 실제 서버 로그인 시 `CurrentUser.initialDestination`을 사용해 동일한 분기를 연결한다. 해당 동의 갱신 API 본문은 이번 첨부에 없으므로 서버 구현을 임의로 만들지 않는다.

## 아직 필요한 원본

F-04 이후 본문이 포함된 완전한 HTML 또는 API 원본을 받아야 나머지 계약을 통일할 수 있다. 이번 변경은 실제 회원가입·토큰 인증·소셜 로그인·AI 분석·서명 URL 처리 완료를 뜻하지 않는다.

## 검증

정적 분석 오류 없음. API 응답 분기·약관 버전 생략·가입 후 로그인 재시도·온보딩 완료·필수 동의 복원·로그아웃 및 화면 테스트 30개 통과. 실 서버 인증·업로드는 아직 검증 대상이 아니다.
