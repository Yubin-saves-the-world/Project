# 최종 기준 문서

이전의 잘린 API 첨부 기준은 [이전 기록](README.partial-baseline.md)으로 보관합니다. 이제 팀장이 최종본으로 지정한 [기능명세서·API·ERD](../final-specs/README.md)를 우선합니다. 이전 제안 문서와 충돌하면 최종본을 따릅니다.

최종 문서: 기능 25개(MVP 11·2차 10·확장 4), API 96개(MVP 35·2차 35·확장 26), ERD 34개 테이블·273개 컬럼·49개 FK 관계.

기본 계약은 `/api`, JSON snake_case, JWT 7일·refresh 없음, 필수 동의 4개, 가입 후 별도 로그인, 신체정보 등록 시 온보딩 완료, 로그아웃 시 서버 계정·기록 유지입니다.

구글·카카오 로그인 모두 **2차**이며 각각 `/api/auth/oauth/google`, `/api/auth/oauth/kakao`입니다. `GET /api/users/me`의 `email`은 카카오 계정에서 null일 수 있습니다. 동의 갱신은 `PATCH /api/users/me`로 확인됐습니다.

현재 앱은 프론트 미리보기이고 서버·OAuth 인증·사진 업로드·AI 요청은 연결 전입니다. 최종 계약이 정해졌다는 것과 전체 기능 개발이 완료됐다는 것은 다릅니다. 초기 화면, 오류 코드별 입력칸 안내, 설정·탈퇴, SDK와 토큰 저장 등 실제 서비스 연결은 최종 계약에 따라 구현해야 합니다.
