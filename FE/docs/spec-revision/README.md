## 기획서 보완

목표 사용자는 운동을 시작하려는 초보자와 운동·자세 관리 정보를 한곳에서 보고 싶은 사용자다. 핵심 가치는 현재 상태와 사용자가 원하는 방향을 공통 항목으로 정리하고, 추천의 근거를 운동·식단 화면까지 전달하는 것이다. 목표 사진과 동일한 체형 달성이나 의료적 진단을 약속하지 않는다.

세부 목표 1: 테스트 계정이 가입부터 설문, 분석, 목표 등록, 비교, 첫 루틴·식단 확인까지 중단 없이 완료한다. 세부 목표 2: 운동 중 앱을 종료해도 저장된 세션을 복원하고, 완료한 기록을 홈·통계·AI 코치에 동일하게 반영한다. 분석 품질과 성능의 합격 기준은 요구사항 §7에서 별도로 관리한다.

기술 역할: Flutter/Dart는 앱 UI·카메라·로컬 복원·타이머, Spring Boot는 인증·도메인 규칙·저장·작업 조정, MySQL은 구조화 데이터, 비공개 객체 저장소는 원본 사진, MediaPipe Pose는 관절 후보 추출, Qwen은 구조화된 설명·추천·대화에 배정한다. 모델의 정확한 버전·실행 장비는 성능 검증 후 고정한다. Stable Diffusion은 연결된 요구사항이 없으므로 v1 범위에서 제외한다. 이는 기술 도입이나 설치 지시가 아니다.

역할은 원본 인원 구성을 유지한다. 이지한은 BE·통합 및 일정, 황예준은 BE·관리자·데이터 설계, 유빈·김기중은 FE·디자인, 채준혁은 AI 분석·추천 계약을 맡는 기본안이다. 사진·분석·추천 작업 계약과 품질 검증은 BE·AI가 공동 책임지고 FE가 상태 표시를 검증한다.

| 단계 | 산출물 | 완료 조건 |
| --- | --- | --- |
| 1. 계약 확정 | 상태 흐름, JSON 샘플, 모델 입력·출력, 테스트 데이터 기준 | 세 직군이 같은 예시를 해석 |
| 2. 핵심 흐름 | 가입~첫 추천, 실패·재시도 화면 | REQ-001·003·005·006·008·009·011·017 통합 검증 |
| 3. 실행·기록 | 홈, 운동 복원, 타이머, 통계, 프로필 갱신 | 재실행·중복 요청·휴식일 검증 |
| 4. AI·데이터 관리 | 코치 승인, 사진 관리, 탈퇴, 자세 안내 | 승인 충돌·삭제 실패 검증 |
| 5. 확장·인수 | 소셜, 커뮤니티, 제휴·미션·쿠폰·푸시 | 선택한 확장 기능의 의존 기능까지 검증 |

원본 일정은 ‘8월 19일~12월’만 있고 연도·현재 진척·가용 시간이 없다. 따라서 완료 날짜를 만들어 넣지 않고 위 단계를 순서와 완료 조건으로 정의한다. 경쟁 서비스 B·C와 비교표의 O/X는 출처가 없어 검증된 경쟁 분석으로 취급하지 않는다. 서비스명·제품 버전·확인일·근거 링크를 확보한 후에만 대외 자료에 사용한다.

예상 위험과 대응: 분석 실패는 글 입력으로 대체하고, 모델 출력은 서버가 스키마·운동 목록·수치 제한으로 검증한다. AI 지연은 작업 상태와 재시도 화면으로 처리하고, 추천 실패 시 이전 유효 추천을 유지한다. 일정이 부족하면 핵심 흐름을 먼저 완료하며 제휴·미션·커뮤니티는 확장 단계로 분리한다. 기대 효과는 초보자의 정보 탐색 단계 감소, 추천과 수행 기록의 연결, 팀의 앱·서버·AI 통합 경험이며 실측 전 효과 수치를 주장하지 않는다.

## 팀 확인이 남는 외부 조건

동작 규칙은 이 제안안에서 기본값을 정했다. 다만 분석 판정 기준의 검증 데이터, 실제 제휴 계약·쿠폰 코드 공급, 모델·서버 성능, 약관 원문·보관 기간, 배포 일정은 문서만으로 사실을 확정할 수 없다. 각 기능의 출시 조건으로 남기며 관련 기능을 검증 전 활성화하지 않는다. 법률·플랫폼 정책의 최신 적합성을 검증한 문서는 아니다.
