## 2. 체형과 AI 분석 계약

공통 외형 특징은 shoulder_hip_ratio(정면 어깨 너비/골반 너비), torso_leg_ratio(정면 몸통 길이/다리 길이), focus_parts(shoulders/back/chest/core/arms/glutes/legs), 사용자 설명으로 구성한다. 양쪽 동일 조건의 관측값이 존재할 때만 비율 차이를 표시한다. 0인 분모·가려짐·원근 영향으로 사용 불가한 항목은 null과 사유를 반환한다. 비율은 사진상의 비교 지표이며 실제 신체 치수로 표기하지 않는다.

자세 지표는 별도 posture에 둔다. 정면은 어깨·골반 선의 수평 대비 절댓값 각도, 측면은 어깨→귀 선의 수직 대비 전방 각도 후보를 산출한다. 좌우·촬영 방향 및 사용 landmark 목록을 측정 버전에 고정한다. 해당 사진·관절이 없으면 수치와 판정 모두 unavailable이다. 사진에 없는 각도·근육량·등 두께·체지방률을 텍스트 모델이 만들어 채우지 않는다.

원문의 ‘균형 점수’는 검증된 measurement profile에 점수 산식이 등록된 경우에만 제공한다. 값이 없으면 0점 대신 ‘점수 산출 불가’. good/caution 경계값·관절 검출 신뢰도 하한·정규화·점수 산식은 measurement profile에 버전과 검증 근거를 함께 등록한다. 현재 제공 문서에는 근거 데이터가 없어 임의의 임상 경계값을 채택하지 않는다. 프로필 검증 완료 전 production에서 판정·점수 기능은 비활성화한다. 이것은 남겨 둔 암묵적 동작이 아니라 명시적 출시 조건이다.

글 분석은 선호·고민·집중 부위에 기반한 추천을 허용하되 사진 측정과 같은 정확도로 표현하지 않는다. 사진끼리 비교할 공통 수치가 없더라도 목표 부위와 설문 목적에 기반한 추천은 생성할 수 있으며 basis=preference를 표시한다. 비교 우선순위는 사용자 지정 집중 부위 우선, 나머지는 등록된 서버 추천 규칙과 사용 가능 데이터로 결정한다. 각 항목에 basis와 evidence를 반드시 붙인다.

Qwen 출력은 JSON schema, 허용 부위, 존재하는 exercise ID, 사용자 경력·기구·처방 범위를 서버에서 검증한다. 검증 실패 시 내부 보정 1회만 허용하고 실패하면 job을 failed로 종료한다. 설명 문장이 유효한 JSON을 대신하지 않는다. Stable Diffusion 기반 이미지 생성은 v1에 없다.

## 3. 동의와 사진·탈퇴 정책

동의 종류는 terms/privacy/body_photo/ai_processing. 필수 약관·개인정보 동의와 사진·AI 처리 동의를 구분하고 버전·동의/철회 시각을 기록한다. 기존 요구의 ‘사진 수집·AI 분석 별도 동의’를 사진과 AI 처리 두 범위로 명확히 나눈 것이다. 사진 업로드는 body_photo, 모든 개인화 AI 요청은 ai_processing 동의가 필요하다. 미동의 시 설정에서 동의 후 이어가거나 기존 기록 조회만 가능하다.

현재 사진은 비공개 저장소에 보관하고 인증 후 짧은 수명의 접근 URL만 발급한다. 목표 사진은 전부 임시 파일이며 업로드 1시간 내 처리 시작이 없으면 삭제한다. 처리 작업이 끝나면 성공·실패와 무관하게 삭제하며, 작업 중에도 업로드 후 최대 1시간을 넘기지 않는다. 삭제 실패 시 접근을 차단하고 삭제 작업을 재시도한다. 목표 특징·설명은 유지한다. 따라서 특정 사진 속 인물을 식별하거나 연예인 여부를 판정할 필요가 없다.

사진 삭제는 해당 원본과 썸네일 등 파생 파일을 대상으로 한다. 참조 사진 ID는 null로 정리하고 기존 분석 결과는 유지한다. 사진 동의 철회 시 새 업로드를 막고 보유 사진 전체 삭제를 요청한다. AI 동의 철회 시 대기·실행 중 AI 작업을 취소하고 신규 요청을 차단하며, 이미 생성된 결과는 조회할 수 있다. 탈퇴는 결과까지 삭제한다.

탈퇴 API 접수 시 account_status=deleting, auth_version 증가, 토큰·푸시 세션 무효화, 외부 조회 차단을 같은 처리 단위로 실행한다. 이후 비공개 삭제 job이 원본·개인 데이터·백업 삭제 대상 표식을 처리한다. 활성 저장소의 물리 삭제 목표는 24시간 이내이며 지연·실패는 운영 경보 대상이다. 이는 원문의 ‘즉시 삭제’를 ‘즉시 접근 불가, 물리 삭제 확인 후 완료’로 구체화한 제안 변경이다.

백업은 30일 회전 보관을 제안 기본값으로 하며 복구 시 삭제 대상 목록을 먼저 재적용한다. 탈퇴 완료 뒤에는 개인정보 없는 삭제 job 결과와 운영 집계만 남기고 복구용 삭제 대상 키는 백업 만료 후 제거한다. 제휴 계약 등에서 별도 보존이 필요한 경우 출시 전 범위·근거·기간을 별도로 확정해야 하며 이 명세만으로 예외 보존을 허용하지 않는다.

## 4. 운동·타이머·인정 기준

열린 세션은 in_progress 또는 paused이고 사용자당 하나만 허용한다. 시작 시 루틴의 당일 항목을 workout_log_items에 복사한다. 종목·순서·목표 세트·중량·휴식을 고정해 이후 추천 변경의 영향을 받지 않게 한다. 완료·중단한 세션은 다시 열지 않는다. v1에서는 완료 후 기록 수정 API를 제공하지 않는다.

시작·일시정지·재개·종료는 서버 시각을 사용한다. duration_sec는 시작~종료 전체 시간, active_duration_sec는 일시정지 구간을 뺀 시간. 미션은 후자를 사용한다. 일반적인 세트 간 휴식은 활성 시간에 포함한다. 6시간 초과 세션은 자동 aborted 처리하고 미션에 반영하지 않는다. 10분 조건은 단순한 인정 규칙이며 실제 운동 수행을 입증하는 장치는 아니다.

앱은 계정별 로컬 저장소에 현재 log ID, 미전송 세트 요청의 고유 키, timer_expires_at을 저장한다. 저장되지 않은 변경에는 ‘동기화 대기’를 표시한다. 재실행 시 서버 current 조회 후 요청을 순서대로 재전송한다. 세트 요청의 client_set_id로 중복 생성을 방지하고 version으로 동시 수정 충돌을 감지한다. 종료는 미전송 요청이 전송된 뒤 실행하며 오프라인 상태에서는 완료 대기로 보인다. 새 기기에는 이미 서버에 저장된 기록까지만 복원된다.

총 볼륨은 완료 세트의 external_weight_kg × reps 합이다. 맨몸 종목은 0kg이며 체중을 임의 합산하지 않는다. 반복 수는 1~200, 중량은 0~500kg, 세트 번호는 양의 정수다. 편측 종목도 사용자가 입력한 횟수를 그대로 합산하고 자동 두 배 처리하지 않는다. 이 정의를 화면 도움말에 표시한다.

기본 운동일은 빈도별 2=[월,목], 3=[월,수,금], 4=[월,화,목,금], 5=[월,화,수,금,토], 6=[월,화,수,목,금,토]다. 사용자는 같은 개수의 요일로 바꿀 수 있다. 예측 시간은 각 세트의 설정 반복 소요 시간과 세트 간 휴식의 합이며 실제 소요 시간과 구분한다. 기본 반복 소요 시간은 prescription에 3초/회로 등록하고 종목별 조정한다.

타이머 완료 알림은 서버 푸시가 아닌 기기 로컬 알림이다. 앱 강제 종료·OS 제한 때문에 알림 전달을 보장하지는 않으며 재실행 시 절대 만료 시각 기준으로 상태를 복원한다. 완료된 세트 재동기화만으로 타이머를 다시 시작하지 않는다. 일시정지·운동 종료·세트 완료 취소 시 연결 타이머를 취소한다.

## 5. 추천 갱신과 홈 상태

users.setup_state는 저장된 별도 진실값 대신 서버가 계산한다. 우선순위는 consent_required → survey_required → analysis_required → goal_required → comparison_required → recommendation_required → ready. 이때 consent_required는 현재 필수 약관 또는 ai_processing 동의가 없는 경우다. body_photo 미동의는 사진 경로만 막으며 글 분석 경로를 막지 않는다. 진행 중 작업은 setup_state와 별개로 active_jobs에 제공한다. 글 분석 기능을 배포하지 않는 단계에서는 사진 대체 경로를 숨기고 사용 가능 기능을 capabilities로 명시한다.

프로필·알레르기 revision이 바뀌거나 활성 분석·목표가 달라지면 기존 비교·추천을 stale로 표시한다. 기존 루틴은 운동 가능 상태로 유지하되 새 알레르기에 맞지 않는 식단·제휴 추천은 바로 노출을 중단한다. 사용자가 재추천하면 비교를 먼저 생성하고 그 결과로 루틴·식단을 각각 생성한다. 부분 성공은 각각 표시하며 실패한 영역만 재시도한다. 새 결과가 유효할 때 해당 영역을 원자적으로 활성 전환한다.

목표 수정은 새 revision 생성이며 성공할 때만 active_goal_body_id 변경. 목표 삭제는 해당 사용자의 목표 revision 전체 삭제 요청으로 처리한다. 이를 참조한 과거 비교는 goal_body_id=null로 바꾸고 비식별 비교 요약 snapshot을 유지하되 현재 추천은 stale 표시한다. 삭제 확인 화면에 이 범위를 안내한다.

분석·목표·추천 작업이 여러 개 동시에 진행되면 같은 사용자·같은 대상에 가장 최근 접수된 작업만 자동 활성화 후보가 된다. 완료 시 입력 revision과 현재 활성 입력을 다시 검사한다. 뒤늦게 끝난 이전 작업은 이력에는 저장하되 활성 포인터를 덮어쓰지 않는다. 오래된 입력의 추천은 INPUT_REVISION_CHANGED로 종료하고 활성 추천으로 게시하지 않는다. 사용자가 과거 분석을 직접 활성화한 경우에도 그 이전에 접수한 작업이 선택을 덮어쓰지 않도록 사용자 행 잠금과 선택 시각을 함께 검사한다.

주간 루틴은 사용자·주 시작일별 활성 버전 1개, 식단은 사용자·적용일별 활성 버전 1개. AI 수정 승인도 새 루틴 버전을 만든다. 승인 시 원본 루틴이 활성 상태가 아니면 409. 현재 날짜의 진행 중 또는 완료 운동이 있으면 그 날짜는 수정 대상에서 제외하고 다음 미실행 운동일부터 변경한다. 승인 재전송은 기존 적용 결과를 반환한다.

계획 달성은 해당 날짜에 계획 루틴을 참조하여 완료 세트 1개 이상 있는 completed 세션이 하나 이상 존재할 때 인정한다. 미션 인정은 별도로 10분 조건이 추가된다. 연속 운동일은 완료 세트가 있는 completed 세션 날짜의 실제 연속 일수다. 오늘 미실시·어제 실시 상태는 어제까지의 연속일을 표시하고 오늘 자정까지 기회를 유지한다. 정규 휴식일에는 streak 감소를 비난하거나 위험 알림을 보내지 않는다.

## 6. 운영 정책

AI 질문 한도는 Asia/Seoul 현지 날짜별 성공 30회. 작업 접수 시 사용권을 원자적으로 예약하고 실패·취소 시 환원한다. 같은 idempotency key의 재요청은 추가 차감하지 않는다. 진행 중 예약까지 포함해 30회면 429. 날짜가 바뀌어도 실패 환원은 원래 예약일에 적용한다.

식단 생성은 버전 있는 nutrition profile의 결정적 함수로 kcal·영양소를 산출한다. 입력에는 나이·키·체중·성별·활동 수준·목적이 포함된다. unspecified를 지원하는 검증된 계산 경로가 없으면 임의 성별을 대입하지 않고 NUTRITION_PROFILE_UNSUPPORTED를 반환한다. 목표 신체 비율 차이로 단백질을 자동 증량하지 않으며 운동 목적·체중 기준의 이유만 설명한다. 식품 마스터의 성분·알레르겐·수량으로 검증한 메뉴만 출력한다. 이름 비교만으로 알레르기 안전을 확정하지 않는다. 지원하지 못하는 알레르기 조건은 추천 불가와 수정 안내를 반환한다.

미션 배정은 유효한 계약·충분한 쿠폰 재고가 있을 때만 시작한다. 시작 시 쿠폰 코드 1개를 해당 사용자 미션에 예약하며 성공 시 발급, 실패 시 반환한다. 주중 신규 사용자는 다음 온전한 주부터 참여하고 현재 주는 참여 예정으로 표시한다. 주중 프로필 변경은 다음 주 미션에 적용한다. 주간 마감 시 미달은 failed. 발급은 user_mission_id를 유일 키로 트랜잭션 처리한다. 진행률은 인정 일수/목표 일수, 최대 100이다.

쿠폰 상태는 available/used/expired. 날짜 비교는 expires_at 미만까지만 유효하고 used_at이 있으면 used가 우선한다. 실제 제휴사 검증이 없는 수동 사용 표시는 usage_source=self_report로 저장하고 ‘앱에서 사용 처리’라고 표시한다. 제휴사 확인 연동은 v1 범위 밖이다. 발급된 쿠폰의 혜택·코드·기한은 정의 수정에 따라 바뀌지 않는다.

신고 3회는 같은 대상의 서로 다른 신고자, status=pending인 신고 기준이다. 중복 신고는 기존 결과 반환. 자동 숨김은 게시글·댓글 모두 적용한다. 관리자가 restore하면 관련 pending 신고를 dismissed로 정리하고 복구한다. delete는 관련 신고를 resolved로 정리한다. 관리자는 본인 글이 아니어도 moderation API로 조치할 수 있으며 일반 사용자 삭제 API와 권한을 분리한다.

푸시는 device별 토큰을 등록하되 일일 예산은 사용자 기준이다. 한 notification_delivery 아래 여러 기기로 동일 알림을 보낼 수 있고 앱은 notification_id로 중복 표시를 억제한다. 매일 활성 설정 중 우선순위가 가장 높은 발송 가능 종류를 하나 선택하고 해당 시각에 전송한다. 발송 직전 조건을 다시 확인하고 조건 해소 시 그날 알림은 취소한다. 외부 푸시 시스템의 재전달까지 정확히 1회를 보장하지는 않으며 서버 발송 의도는 1회로 제한한다. 기본 위험 시각은 21:00이며 다른 기본 알림은 workout 18:00, diet 12:00, 최초 enabled=false다.
