# MOVID FE 작업 지침

## 작업 위치와 시작점

- 실제 개발 대상은 이 파일이 위치한 Flutter 프로젝트다. 현재 절대 경로는 `/Users/yubin/StudioProjects/Project/FE`이며 Git 루트는 상위 `Project`다.
- `/Users/yubin/StudioProjects/FE`는 예전 별도 개발 폴더다. 현재 채팅의 cwd가 예전 폴더여도 앱 변경은 실제 개발 대상에서 수행한다. 두 폴더를 동기화하거나 통째로 덮어쓰지 않는다.
- 새 채팅에서는 작업 전에 [프로젝트 인수인계](docs/project-context/README.md)를 읽고, 요청과 관련된 현재 코드 및 상세 문서를 확인한다.
- 최신 서버 API 계약은 `docs/team-handoff/2026-10-25/api/openapi.yaml`, 현재 구현 상태는 `docs/project-context/README.md`의 최신 날짜 항목을 확인한다. 팀 전달 자료의 ‘제안/제외/미연결’ 설명은 이후 사용자의 확정 사항과 현재 코드보다 우선하지 않는다.
- 최종 요구사항 원본은 `docs/project-context/MOVID_requirements_v0.3.docx`다. 이후 사용자가 변경한 정책은 인수인계 문서에 별도로 기록되어 있다. 기획과 기존 API가 다르면 계약을 임의로 만들지 말고 차이를 명시한다.

## 사용자가 정한 작업 범위

- 요청한 작업만 수행한다. 요청하지 않은 디자인·기능·파일 구조 변경은 하지 않는다.
- 기존 로그인·회원가입·온보딩·홈 기능과 다른 팀원의 변경을 보존한다. 파일 삭제나 기존 기능 변경이 불가피하면 먼저 보고한다.
- 나중에 사용할 파일·기능 폴더·README·`.gitkeep`은 미구현이라는 이유로 삭제하지 않는다. 정리가 요청되면 실제 불필요·중복 여부와 참조를 확인한 항목만 대상으로 한다.
- `main()`과 `bootstrap()` 분리는 향후 개발을 위해 유지하기로 했다.
- Figma 구현 요청은 실제 Flutter 코드 수정 요청으로 해석한다. Figma 파일 자체의 변경은 사용자가 명시적으로 요청한 경우에만 한다.
- Git 커밋과 Push는 별도 요청 없이 실행하지 않는다.

## 변경과 검증

- 먼저 Git 상태와 관련 파일을 읽는다. 기존 수정·미추적 파일을 자신의 작업으로 오인하거나 되돌리지 않는다.
- UI는 기존 색상·폰트·간격 체계를 따른다. 새 오류 메시지·모달·시트도 기존 디자인과 일치시킨다. 입력 오류로 하단 주요 버튼이 화면 밖으로 밀리지 않게 한다.
- 계정별 로컬 데이터, 기존 운동 기록 및 저장 형식을 보존한다. 로컬 개발 기능을 실제 인증·메일 발송·분석·서버 저장으로 설명하지 않는다.
- 코드 변경 후 `flutter analyze`와 변경 범위에 맞는 테스트를 실행한다. 인증·온보딩·홈 연결에 영향을 주면 관련 회귀 테스트도 확인한다. 문서만 변경한 경우 앱 테스트를 불필요하게 반복하지 않는다.
- 결과는 한국어로 변경 내용, 검증 결과, 남은 제한을 구분해 간단히 보고한다. 코드 설명은 초보 개발자가 이해할 수 있도록 역할과 흐름 중심으로 한다.
- 중요한 정책이나 구현 상태가 바뀌면 인수인계 문서도 갱신한다. 검증 결과에는 실행 시점과 범위를 표시한다.


## iOS 통합 테스트와 사용자 데이터 보호

- 사용자가 쓰는 시뮬레이터에서 `flutter test integration_test/...`를 실행하지 않는다. Flutter 통합 테스트 러너는 종료 시 앱을 uninstall하므로 테스트 키를 분리해도 동일 bundle ID의 일반 앱 데이터가 삭제된다.
- iOS 통합 테스트는 별도 QA 시뮬레이터에서 수행한다. 사용자 시뮬레이터에는 앱 삭제 없이 일반 앱 업데이트만 설치하며, 확인 목적으로 로그인·가입 정보를 덮어쓰지 않는다.
