흰색 이미지는 오류 처리 검사용 합성 입력이다. 실제 사진이나 학습 자료로 세지 않는다. 정상 비교 요청의 확인 필드 이름은 `capture_conditions_confirmed`다.

Flutter용 실제 HTTP 흐름도 통과했다: Spring 로그인 → 사진 업로드 → 분석 요청 → 결과 조회 → 시험 업로드 삭제. 결과는 어깨 2.94°, 골반 3.12°, 어깨/골반 비율 1.59, 상체/다리 비율 0.45였다. **이번 검사는 Flutter UI 클릭·카메라 촬영 검사가 아니다.** GitHub에서 새로 내려받은 ZIP의 다른 컴퓨터 설치 성공도 뜻하지 않는다.

전체 실제 JSON은 개인정보·사진 표현을 포함할 수 있어 비공개 로컬 `AI/.runtime/verification_20261103/`에 보관한다. 공개 응답 규격은 `api-contract/`를 참고한다. 변경은 AI 폴더에만 있다. FE/BE 원본은 수정하지 않았다.

## 아직 완료되지 않은 작업

### 후속: 시험 후보 8개 저장·부분 등급 평가 완료

사용자가 기존 학습 인물과 모두 겹치지 않는다고 명시적으로 확인했다. 얼굴 인식으로 자동 확인한 것이 아니다. 라벨은 weak 5개, medium 3개이며 clear는 없다. 사진 5장은 같은 행사 그룹 하나로 보수적으로 관리한다. 학습에 합치지 않았고, 라벨 저장 전에 고정한 v9 모델로 평가했다.

- 전체 정답: 5/8 = 62.5%.
- weak 재현율: 4/5 = 80.0%.
- medium 재현율: 1/3 = 33.3%.
- 관측된 두 등급만의 macro F1: 0.5636.
- clear 표본이 없어 3등급 전체 macro F1은 `null`로 반환한다.
- 모델 점수 0.6 이상으로 수락된 결과: 1/8. 그 1개는 정답이다. 이를 일반적인 100% 정확도로 주장하지 않는다.

독립 인물 확인은 사람 진술에 근거하며, 단일 행사·소규모·일부 등급 시험이다. 이 결과만으로 v9를 운영에 적용하지 않는다. 운영은 v4 유지다. 이미 확인한 이 시험 결과에 맞춰 설정을 조정하면 새 독립 시험 성적으로 주장할 수 없다.

평가 도구는 기본적으로 모든 등급을 요구한다. `--allow-missing-test-classes`를 명시한 경우에만 부분 평가를 허용하며 누락 등급·평가 범위를 반환하고 전체 등급 macro F1을 비운다. 인물 확인·모델 고정·학습 자료와 중복 검사 등의 보호 절차는 그대로 적용한다.

1. 부족한 clear 등급과 다른 출처·행사의 추가 시험 자료 확보. 위 8개의 라벨과 인물 중복 확인은 완료했다.
2. 통과 기준을 사전에 정하고 독립 평가를 완료한 모델의 운영 적용 결정.
3. 실제 Flutter 화면에서 최신 응답 표시 확인, 실제 카메라 촬영 시험. 상세 표시 변경이 필요하면 FE 담당 협업이 필요하다.
4. 추천 우선 부위·루틴은 구현 완료가 아니다. 사진의 비율 차이나 윤곽 약함을 근육 부족·질환으로 간주하지 않는다. 별도 설계 초안 `ROUTINE_HANDOFF_PROPOSAL.md`를 참고한다.
