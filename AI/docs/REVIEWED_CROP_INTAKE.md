# 원본·크롭을 직접 확인한 라벨링 후보 준비

이번 작업은 AI/에만 적용했습니다. 기존 라벨·학습 모델·FE·BE는 변경하지 않습니다. 새 후보의 최종 윤곽 등급은 사람이 저장합니다.

## 이번 준비 결과

Kaggle 사람 분할 자료에서 144장 미리보기를 1차 검토한 뒤, 원본을 직접 확인한 9장의 상완 크롭 12개를 AI/.runtime/kaggle_arm_batch_v2에 준비했습니다. 그 밖의 미리보기 사진은 이번 라벨링 화면에 제공하지 않습니다. 기존 kaggle_arm_batch_v1의 2개 후보와 기존 라벨 파일도 유지했습니다.

- 새 후보 화면: http://127.0.0.1:8007/
- 새 묶음 이름: kaggle_arm_batch_v2
- 새 후보: 12개 영역 / 원본 사진 9장 / 임의로 생성한 윤곽 라벨 0개
- 같은 사진의 상완들은 같은 kgv2_photoNN 임시 ID를 사용합니다. 사진이 다르다는 이유만으로 사람이 다르다고 확정한 것은 아닙니다. 같은 인물이 여러 사진에 있으면 사람이 같은 ID로 수정해야 합니다.
- 자동 포즈 제안 중 전완·손·가림이 섞인 영역은 그대로 승인하지 않았습니다. 실제 상완 위치와 최종 크롭을 직접 확인했습니다.

스포츠·일상복 사진의 상완이 보이는 후보입니다. 자세·조명·해상도 영향은 남아 있습니다. 흐릿함이나 가림 때문에 판단할 수 없는 사진은 weak 대신 exclude로 저장합니다. 9장의 사진을 검증된 서로 다른 인물 9명으로, 또는 12개 영역을 독립된 사람 12명으로 계산하지 않습니다.

## 정확히 확인한 크롭의 준비 경로

```sh
.venv/bin/python scripts/prepare_reviewed_crops.py \
  --manifest .runtime/kaggle_screening_v2/reviewed-crop-manifest.json \
  --output .runtime/kaggle_arm_batch_v2

.venv/bin/python scripts/label_contours.py \
  --dataset .runtime/kaggle_arm_batch_v2 --port 8007
```

현재 컴퓨터에는 이미 위 결과가 준비돼 있으므로 첫 명령을 반복할 필요가 없습니다. 기존 출력이 있으면 덮어쓰지 않습니다. 원본·매니페스트·크롭·특징·라벨은 비공개 runtime에만 보관합니다. GitHub ZIP에는 코드와 검사만 포함됩니다.

입력 매니페스트의 각 항목에는 원본 경로·SHA256, 무손실 PNG 크롭 경로·SHA256, 정규화된 원본 크기·크롭 좌표, 원본/크롭/상완 위치/피부 확인 플래그, 검수자와 확인 내용이 필요합니다. 원본을 정규화한 뒤 지정 영역의 픽셀과 검수 PNG가 실제로 같은지 검사합니다. 다른 부위를 잘라 두고 좌표만 상완이라고 쓰는 픽셀 불일치를 거절합니다. 해시·픽셀 대응 검사는 의미상 상완임을 자동 판정하는 기능은 아니며 실제 위치 확인은 검수자의 역할입니다.

가늘고 긴 상완을 다루는 이 명시적 검수 경로는 짧은 축 64px·긴 축 128px 이상을 요구합니다. 이는 검수 후보의 최소 픽셀 조건이며 정확도가 검증된 판정 기준이 아닙니다. 기존 원본 자동 준비 경로의 해상도 기준이나 운영 분류기의 보류 임계값은 바꾸지 않았습니다. 작은 영역은 최종 라벨링 시 추가 확인합니다.

모든 입력을 검사한 뒤 동결 DINOv3의 768차원 특징을 추출합니다. 임시 폴더에서 준비를 마친 뒤 출력으로 옮기므로 실패한 도중의 폴더를 완료된 데이터셋으로 남기지 않습니다. annotations.json은 생성하지 않습니다. 기존에 격리한 폴더나 입력 폴더 밖의 파일은 받지 않습니다.

## 검수 이후 변경 방지

새 준비 경로의 dataset.json에는 review_release=source_and_crop_hash_v1과 실제 제공할 원본·크롭의 해시를 기록합니다. 라벨 서버는 이 표시가 있는 자료에서 검수 해시가 없거나 파일이 바뀌면 시작을 거절합니다. 기존 데이터셋은 기존 계약을 유지합니다.

원본 검수는 라벨 정답 작성과 다릅니다. skin_visible_confirmed는 근육 발달·근육량의 정답 라벨이 아닙니다. 이번 작업으로 새 모델을 학습하거나 정확도 개선을 주장하지 않습니다.

## 라벨 저장 후 통합

모든 새 후보를 실제 저장한 뒤 새 출력 폴더로 통합합니다.

```sh
.venv/bin/python scripts/merge_reviewed_datasets.py \
  --include kaggle2=kaggle_arm_batch_v2 \
  --output .runtime/merged_with_kaggle_v2
```

추가로 v1도 저장했다면 --include kaggle1=kaggle_arm_batch_v1을 함께 지정할 수 있습니다. 동일 인물·원본 중복·분할 조건과 학습 준비 검사는 그대로 적용합니다. 새로운 등급에 충분한 서로 다른 인물이 없으면 교차검증을 억지로 통과시키지 않습니다.

검사 92개 통과: 미검수 입력 거절, 원본 변경 거절, 해시가 일치해도 다른 원본 영역인 크롭 거절, 격리 경로 거절, 라벨 서버의 변경된 파일·알 수 없는 검수 형식 거절과 기존 계약 검사를 포함합니다. 실제 새 12개 후보의 원본/크롭 해시와 특징 추출을 확인했고 브라우저에서 0/12 묶음이 열리는 것도 확인했습니다.
