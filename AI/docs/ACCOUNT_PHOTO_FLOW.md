# 계정 사진 분석부터 코치까지

2026-11-04. AI 자체 웹 시연이며 원본 Flutter·BE 코드를 수정하지 않았다.

## 실행

프로젝트 루트에서 `bash AI/run-flutter.sh --no-app --require-coach`를 실행하고 출력된 `/coach/account` 주소를 연다. 기존 Flutter 설치 없이 서버와 웹 화면만 실행한다. Python 3.12, JDK 17 이상, Ollama와 로컬 qwen3:4b가 필요하다. DINOv3는 해당 계정의 Hugging Face 승인·CLI 로그인이 필요하며 `--geometry-only`를 추가하면 특징 추출 없이 관절 수치만 측정한다. ZIP에는 모델·사진·토큰·DB가 없다.

1. 계정에 로그인한다. 최초 로컬 시연 계정은 demo@movid.local / movid1234이며 기존 계정의 비밀번호를 변경하지 않는다.
2. 정면 JPG/PNG 한 장과 선택 측면 한 장을 업로드한다. 파일당 10MB 이하이며 서버에서 형식·해상도·촬영 조건을 추가 검사한다. HEIC는 변환이 필요하다.
3. 같은 페이지에서 측정 카드와 촬영 조건을 확인한다. null은 0으로 바꾸지 않는다. 측면 누락과 인식 부족을 별도 안내한다.
4. 완료된 분석은 같은 계정의 코치 참고 목록에 자동 선택한다. 각도·비율만 모델에 전달하고 사진·특징 벡터는 전달하지 않는다. 사용자가 ‘참고하지 않음’을 선택할 수 있다.
5. 전체 응답은 JSON으로 저장할 수 있다. 원본 사진은 보관 목록에서 삭제한다. 사진 삭제는 측정 기록이나 대화 삭제와 다르다.

브라우저 저장소에 비밀번호·토큰을 넣지 않는다. 새로고침 시 다시 로그인해야 한다. 이 화면의 기록은 AI 브리지 SQLite에 저장하며 기존 BE MySQL 기록과 자동 동기화하지 않는다.

## 사용하는 기존 API

| 단계 | 요청 |
|---|---|
| 로그인 | POST /api/auth/login |
| 사진 저장 | POST /api/photos, multipart image·type=current·side=front 또는 side |
| 분석 시작 | POST /api/body-analyses/photo, JSON photo_id·선택 side_photo_id |
| 결과 확인 | GET /api/body-analyses/{analysis_id} |
| 목록 갱신 | GET /api/body-analyses?page_size=100 |
| 코치 질문 | POST /api/ai-coach/messages, content·profile·analysis_id |
| 원본 삭제 | DELETE /api/photos/{photo_id}, 성공 204 |

인증과 사진·분석·대화의 계정 소유권은 서버에서 확인한다. 성공 응답을 받지 못한 POST는 자동 재전송하지 않는다. 네트워크 오류 후에는 기록을 먼저 확인한다.

## 실패·시간 초과·삭제 처리

- 분석 실패는 카드에 0점으로 표시하지 않고 오류 메시지와 코드를 표시한다. 실패 분석은 일일 횟수에서 제외한다.
- 화면은 약 100초까지 상태를 확인한다. 통신 오류나 대기 시간 초과 시 마지막 접수 번호를 유지해 같은 분석을 다시 조회한다. 페이지 새로고침 시 이 메모리 정보는 사라지므로 완료 목록을 확인한다.
- 정면 저장 후 측면 업로드나 분석 접수가 실패해도 앞서 저장된 사진은 남을 수 있다. 보관 목록을 열어 직접 정리한다. 사진은 최대 20장 보관한다.
- 시간 초과 결과는 뒤늦게 끝난 작업으로 덮어쓰지 않는다. 실제 작업이 파일을 사용하는 동안에는 시간 초과 상태에서도 삭제를 거절한다(409).
- 사진 업로드의 DB 저장 실패 시 새 파일을 정리한다. 삭제는 DB 저장 성공 후 원본을 지운다. 파일 정리 실패 시 접근을 차단하고 PHOTO_DELETE_INCOMPLETE(503)를 반환한다. 같은 사진 ID의 삭제를 재시도할 수 있다.
- 인증 서버의 장애·비정상 상태는 AUTH_SERVER_UNAVAILABLE(503)이다. 실제 인증 거절(401·403)과 구분해 일시 장애로 로그인 세션을 지우지 않는다.
- 잘못된 서명·삭제와 읽기가 겹쳐 없어진 사진은 404로 처리한다.

## 검증 결과와 한계

기존 공식 모델 캐시와 로컬 인증 서버로 정면+측면 업로드 → 비동기 분석 → 측정 8개 → 계정 코치 전달 → Qwen3 생성 → 저장 기록 조회 → 시험 사진 원본 삭제를 실제 HTTP로 확인했다. 해당 시험에서 어깨 2.94°, 골반 3.12°, 측면 귀·어깨 9.13°가 계산됐고, 코치가 어깨·골반 숫자를 동일하게 설명했다. 이는 한 사진의 기능 검증이며 측정 정확도 평가가 아니다.

브라우저 자동 조작이 현재 앱 설정에서 비활성화되어 이번 변경의 실제 화면 클릭·시각 검증은 수행하지 못했다. 화면 로직의 Node 테스트와 실제 HTTP 연결 검증을 구분한다. 모델의 모든 답변 정확성을 보장하지 않는다.

근육 발달 점수·건강 판정·사진으로 정한 운동 우선 부위는 여전히 검증된 기능이 아니다. 기존 Flutter 코치 화면과 실제 BE의 Qwen3 연결 작업도 별도 담당 범위다. 이 화면의 성공을 원본 앱 전체 연결 완료로 해석하지 않는다.
