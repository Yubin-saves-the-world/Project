# 목표 비교·기본 루틴 연동 초안 — 합의 전, 미구현

기존 분석 API는 측정값 차이를 반환하지만 추천 우선 부위·루틴은 구현하지 않았다. 현재 응답의 `priority_parts: []`, `priority_parts_status: not_implemented`, `routine_status: not_implemented`를 실제 추천으로 표시하지 않는다. 이 문서는 향후 FE·BE 담당자와 합의하기 위한 초안이며 기존 API 계약을 변경하지 않는다.

## 입력과 추천 근거

- 목표 사진이 있으면 비교 가능한 측정값의 차이만 제공한다. 비율 차이나 윤곽 등급으로 근육 부족 부위·치료 운동을 결정하지 않는다.
- 사용자가 직접 선택한 운동 목표·선호 부위가 있으면, 추천 근거를 `user_selected_goal`로 명시한다. AI가 사진으로 발견한 부족 부위라는 문구를 쓰지 않는다.
- 목표가 없으면 경험 수준·주당 가능 횟수·보유 장비에 맞는, 사전에 검수된 일반 전신 루틴 후보를 기본값으로 제안하는 방식을 BE와 합의한다. 필요한 정보가 없으면 질문하거나 정보 미확인 상태를 표시한다.
- 주의 항목이 비어 있다고 운동 제한이 없다고 간주하지 않는다. 주의 항목의 미입력·없음 확인·입력됨을 구분한다. 개인별 의료적 판단이나 제한 해제를 AI가 수행하지 않는다.

## 책임 분리 제안

BE: 사용자 선호·빈도·경험·장비·주의 항목 보관, 검수된 운동 목록과 루틴 구성 규칙, 루틴 저장·중복 요청 처리.

AI: 측정 가능 여부·차이·근거·한계를 반환. 향후 추천 문장을 생성하더라도 합의된 운동 목록·규칙 밖의 운동이나 건강 판정을 만들지 않는다.

FE: 기본 루틴인지 사용자 목표 기반인지 표시하고, 미구현·입력 부족·생성 실패·정상 결과를 구분한다.

현재 AI 폴더만 수정할 수 있으므로 FE·BE의 저장·화면·루틴 코드는 변경하지 않았다. 필드 이름·오류 코드·검수된 운동 목록·기본 규칙을 담당자와 합의한 뒤 별도 구현해야 한다.
