# AI 코드 정리·조회 최적화

변경 범위는 AI/다. FE·BE 원본, 개인 사진·라벨·모델·기존 DB는 정리 대상으로 삭제하지 않았다. 이메일 인증과 원본 Flutter 코치 탭 연결이라는 담당 영역 차단 항목은 그대로다.

## 조회 개선

- 운동 기록은 SQL LIMIT/OFFSET으로 해당 페이지만 읽는다. 페이지의 세트는 한 번에 읽어 묶고, 전체 통계는 DB의 로그별 집계를 순회한다. 기간 전체의 세트와 상세 JSON을 메모리에 쌓지 않는다.
- 총 개수·페이지·통계는 하나의 읽기 트랜잭션에서 조회해 같은 시점의 내용을 반환한다. 비어 있는 페이지에도 전체 기간 통계와 개수는 유지한다.
- 진행·중단 기록은 목록 개수에는 포함하되 완료 세트 합계와 달력 날짜에는 포함하지 않는 기존 규칙을 유지했다. 계정·날짜·상태 필터도 그대로 적용한다.
- 운동량은 기존 상세 응답처럼 로그별로 소수 둘째 자리 반올림한 뒤 합산한다. 페이지에 포함되지 않은 기록도 통계에 포함한다.
- 분석 이력은 큰 payload를 읽지 않고 목록용 필드만 조회한다. 사진 목록도 DB에서 페이지를 나눈다.
- 분석 소유자와 루틴별 운동 조회에 인덱스를 추가했다. 기존 데이터는 다시 만들지 않는다.

## 구조·오류 처리 정리

공통 BridgeError·UTC 시각·ID와 페이지 범위를 bridge/common.py로 옮겼다. workouts가 api 모듈에서 오류 클래스를 가져오던 의존성을 제거했다. 기존 bridge.api의 import 경로는 계속 사용할 수 있다.

SQLite와 JavaScript 양쪽에서 안전하게 표현하는 양의 정수 범위를 확인한다. 매우 큰 분석·사진 ID 또는 페이지 번호가 SQLite OverflowError로 이어지지 않도록 4xx로 처리한다. 인증 서버가 비정상적으로 큰 사용자 ID를 반환하면 서비스 응답 오류로 처리한다.

진행 중인 운동은 6시간 만료 여부를 확인한 뒤 세트를 수정·삭제한다. 중단된 기록도 세트 변경을 거절한다. 완료된 기록은 기존의 버전 검사와 마지막 완료 세트 보호 규칙에 따라 수정할 수 있다. 열람과 기록 전체 삭제는 기존대로 가능하다.

README에서 이미 구현된 홈·플랜·기록·사진 비교를 미구현으로 적던 문장을 고치고 웹 검사 명령에 사진 모듈 검사도 포함했다. API 응답 키와 날짜·부피·완료 판정 방식은 유지했다.

## 검증

Python 전체 테스트 205개 통과. 추가 회귀 검사는 큰 ID·페이지, 계정별 페이지 순서·총 개수, 완료/진행/중단 필터, 페이지 밖 통계, 소수 무게 반올림, 만료 기록 수정 거절을 포함한다. 120개 계정 기록을 준비하고 페이지 렌더링은 3개만 수행하며 SELECT가 최대 4번인지 검사한다.

별도 합성 성능 검사(기록 1,000개, 세트 12,000개, 페이지 20개):

| 항목 | 이전 방식 | 개선 방식 |
|---|---:|---:|
| SELECT 횟수 | 2,001 | 4 |
| 로컬 단일 측정 | 77.09ms | 7.02ms |

같은 페이지와 전체 합계가 일치했다. 이 시간은 현재 Mac의 합성 자료 단일 측정이며 실사용 지연이나 고정 배속 향상을 보장하지 않는다. DB의 전체 기간 집계 작업량 자체가 상수 시간이 되는 것은 아니다. 임시 합성 DB는 검사 후 정리했다.

재검증은 AI 폴더에서 `MPLCONFIGDIR=.runtime/matplotlib .venv/bin/python -m unittest discover -s tests -q`로 수행한다. 모델을 새로 내려받거나 기존 자료를 재학습하지 않는다.
