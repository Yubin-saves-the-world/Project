# AI-only 연결·배포 안내

사용자가 2026-11-03에 다시 확정한 제한: **AI 폴더만 수정. FE·BE 수정 금지.**

## 이번 연결

AI 호환 서버에 아래 인증 경로를 추가했다. 실제 Spring의 `/api/users/me`로 토큰·사용자·AI 동의를 검증하고 사용자별 로컬 SQLite에 완료된 대화 쌍만 저장한다.

- GET /api/ai-coach/messages → 최근 20개 messages.
- POST /api/ai-coach/messages, `{"content":"질문"}` → user_message, assistant_message.
- DELETE /api/ai-coach/messages → 삭제한 메시지 수.

대화 역할·문자열·시각·message_id는 받은 BE 코치 형식을 따른다. 모델 실패·시간 초과는 오류로 반환하고 고정 문장을 모델 답변으로 저장하지 않는다. 시간표·안내 원칙은 규칙 기반임을 문자열에도 명시한다. 모델 호출과 SQLite 저장 사이에는 긴 DB 트랜잭션을 유지하지 않는다. 두 메시지는 원자적으로 저장하고 사용자가 섞이지 않도록 uid를 인증 결과에서만 가져온다. 보관은 사용자별 최대 100개이며 읽기는 최근 20개다. 생성 중 삭제는 409, 중복 생성은 503이다.

이는 **AI 폴더의 데모 호환 구현**이며 실제 BE의 MySQL 코치 구현을 수정한 것이 아니다. 직접 `/v1/coach/chat` 웹 API는 이와 달리 대화를 서버 DB에 자동 저장하지 않는다.

## 원본 Flutter의 차단 요소

현재 로컬 FE와 확인한 GitHub main의 `main_shell.dart`에는 코치 화면이 `EmptyView`로 남아 있다. 기존 코치 탭은 API를 호출하지 않는다. AI API를 추가해도 이 정적 화면이 자동으로 채팅 화면으로 바뀌지는 않는다.

따라서 아래를 구분한다.

- AI 웹 코치 시연: 가능.
- 인증·Qwen3·사용자별 대화 저장 API: AI 호환 서버에서 가능.
- 원본 Flutter 사진 분석 연결: 기존 호환 서버 경로 사용.
- 원본 Flutter 코치 UI 종단 연결: FE 담당자가 화면을 연결해야 함. 이번 제한 안에서는 변경하지 않음.
- 실제 BE Anthropic 분기를 Qwen3로 교체: BE 담당 작업. 이번에 변경하지 않음.

## 실행

프로젝트 루트에서:

```bash
# AI 웹 사진 분석·Qwen3 코치
bash AI/run-coach.sh

# 인증·사진·코치 대화 저장을 포함한 호환 서버
bash AI/run-flutter.sh --no-app
```

Ollama 실행과 qwen3:4b 모델 준비가 필요하다. DINOv3는 각 환경에서 모델 승인·인증 또는 측정 전용 `--geometry-only` 옵션을 준비한다. 실제 가중치·개인 라벨·DB·토큰은 GitHub ZIP에 포함하지 않는다.

AI 호환 서버의 최초 로컬 계정은 demo@movid.local / movid1234이며 이미 DB가 있으면 기존 비밀번호 설정을 따른다. 공개 배포 계정이 아니다.

## 검증·GitHub 반영

코치 이력 소유권·인증·실패 시 미저장·시간표 출처·삭제 충돌 테스트를 추가했다. 전체 자동 테스트 152개 통과. 변경 경로는 AI 폴더만이며 기존 FE·BE 원본 보호 검사를 유지한다.

게시와 새 ZIP 실행 결과는 최종 작업 응답의 실제 PR·검증 결과로 확인한다. 기존 문서에서 '미게시'로 적은 내용은 당시 작업 스냅샷을 설명한다.

## 계정 코치 화면 추가

`/coach/account`에서 기존 로컬 계정으로 로그인해 Qwen3 대화, 최근 기록 조회, 전체 기록 삭제, 로그아웃을 확인할 수 있다. `bash AI/run-flutter.sh --no-app`으로 실행한 호환 서버에서 이 경로를 연다. 기본 코치 `/coach`의 ‘계정 대화’ 링크로도 이동한다. 독립 코치 서버만 실행하면 계정 API가 없어 로그인할 수 없으므로 호환 서버 실행 안내를 표시한다.

- 토큰은 페이지 메모리에만 보관하며 localStorage·URL에 기록하지 않는다. 새로고침 시 재로그인한다.
- 비밀번호 입력은 로그인 성공 후 비우며 로그아웃 시 화면의 대화를 지운다. 서버 기록은 별도 삭제 전까지 유지한다.
- 질문은 500자까지이며 답변 처리 중 중복 전송·삭제·로그아웃을 막는다.
- 요청 대기 제한은 90초다. 시간 초과 시 서버 저장이 끝났을 수 있어 자동 재전송하지 않고 기록 새로고침을 안내한다.
- 응답은 HTML로 삽입하지 않고 텍스트로 표시한다. 삭제는 확인 창을 거친다.
- 이 화면은 AI 폴더의 웹 시연이며 원본 Flutter 코치 화면 구현을 대체하지 않는다.

## 코치 필수 시연 실행

```bash
bash AI/run-flutter.sh --no-app --require-coach
```

코치를 포함한 시연에서는 이 명령을 사용한다. 모델 준비를 실제 BE 빌드 전에 확인하고, 서버가 뜬 후에도 코치 상태를 다시 확인한다. 모델을 자동으로 내려받거나 다른 모델로 대체하지 않는다. 실패하면 이 실행이 시작한 서버만 종료한다. 기본 실행은 코치가 준비되지 않아도 사진 분석을 사용할 수 있도록 경고와 계정 코치 주소를 출력한다. 원본 Flutter 코치 탭의 연결 여부는 별도로 안내한다.

2026-11-04 변경: 계정 코치 화면과 실행 점검을 PR #24에서 함께 정리한다. 이전에 main에 병합된 PR #23 이력은 공유 이력 보존을 위해 변경하지 않는다.

## 사진 측정값을 참고하는 계정 코치

`POST /api/ai-coach/messages`는 기존 `content` 요청을 유지하면서 선택 항목 `profile`, `analysis_id`를 받는다.

```json
{"content":"선택한 사진의 측정값을 설명해줘","profile":{"goal":"habit","experience":"beginner","weekly_days":3,"minutes":20},"analysis_id":1}
```

`analysis_id`를 생략하거나 null로 보내면 측정값을 전달하지 않는다. 서버는 인증한 사용자의 완료된 분석에서 허용된 각도·비율 5개만 읽는다. 원본 사진·특징 벡터·디버그 이미지·점수는 전달하지 않는다. 클라이언트가 임의 측정값을 보내는 방식은 지원하지 않는다. 타인 또는 없는 분석은 404 NOT_FOUND, 미완료 분석은 409 ANALYSIS_NOT_READY, 참고할 수치가 없거나 유효하지 않으면 422 MEASUREMENTS_UNAVAILABLE을 반환한다. 잘못된 번호·프로필은 422 VALIDATION_FAILED이다.

기존 user_message, assistant_message 외에 context를 반환한다:

```json
{"context":{"analysis_id":1,"measurements_provided":true,"context_used":true}}
```

`measurements_provided`는 수치를 전달했다는 뜻이며 `context_used`는 이번 응답 경로에서 참고했는지를 뜻한다. 규칙 기반 운동 계획은 측정값을 이용해 운동 우선순위를 정하지 않아 context_used=false일 수 있다. 선택은 자동으로 켜지지 않는다. 계정 화면 ‘운동 설정과 사진 측정값 참고’에서 최근 100건 중 완료된 분석을 사용자가 선택한다. 기본 프로필은 습관·초보·주 3회·20분이다. 설정은 요청마다 전달하며 서버 프로필을 변경하거나 운동 루틴을 저장하지 않는다.

검증: 자동 테스트 157개 통과. 기존 로컬 사진과 모델·인증 서버를 사용해 로그인→사진 업로드→분석 완료→analysis_id 전달→qwen3:4b 답변까지 실제 HTTP 요청으로 확인했다. 응답의 measurements_provided=true, context_used=true를 확인했다. 독립 테스트 DB를 사용했으며 원본 Flutter 화면의 검증을 의미하지 않는다. 타인 분석 404, 미완료 409, 빈 수치·잘못된 수치·잘못된 프로필 422 및 기존 content-only 요청 호환성을 자동 테스트로 확인했다.
