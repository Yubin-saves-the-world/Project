# 원본 Flutter 앱으로 로컬 사진 분석하기

## 범위

변경 파일은 전부 `AI/` 안에 있습니다. 프로젝트의 `FE/`, `BE/`, 루트 문서·설정은 수정하지 않습니다. 실행기는 원본 FE/BE를 `AI/.runtime/flutter_demo/`로 복사해 빌드합니다. Dart·Java 소스는 그대로 사용하며, 빌드 도구가 만드는 파일은 복사본에만 생깁니다. 원본 파일 SHA-256을 실행 전후 비교합니다.

이것은 **로컬 시연 구성**입니다. 원본 Spring의 회원·로그인·프로필 API를 실행하고, 기존 Flutter가 요청하는 사진·분석 API는 AI 안의 선택적 연결 계층이 제공합니다. Spring의 BCrypt/JWT 인증을 그대로 사용합니다. 실제 서비스의 공유 DB나 배포 구성을 바꾸지 않습니다.

## 준비

- macOS, Python 3.12, JDK 17 이상, Flutter SDK
- Xcode와 설치된 iOS Simulator 런타임, Flutter iOS 빌드에 필요한 환경
- Hugging Face DINOv3 이용 승인을 받은 계정의 로컬 로그인
- 공식 모델: `facebook/dinov3-vits16-pretrain-lvd1689m`

최신 main ZIP의 프로젝트 루트에서 실행합니다. 첫 실행에는 인터넷 연결과 의존성·모델 다운로드 공간이 필요합니다. 일반 AI 단독 테스트는 기존 `bash AI/run.sh`를 사용합니다.

```bash
bash AI/run-flutter.sh --photo "/사진의/절대경로/test1.jpg"
```

실행기가 AI 가상환경·모델을 준비하고 Spring과 AI API를 시작한 뒤, 별도 **MOVID AI QA** 시뮬레이터에서 원본 Flutter 앱을 실행합니다. Xcode 버전에 따라 화면 앱 이름은 **Simulator** 또는 **Device Hub**입니다. 화면이 자동으로 보이지 않으면 해당 앱에서 MOVID AI QA를 선택합니다. `--photo` 사진은 해당 QA 기기의 앨범으로 가져옵니다. 실제 사진을 인터넷 분석 서비스로 전송하지 않고 로컬 API에서 처리합니다.

이 컴퓨터의 기존 테스트 사진 예시:

```bash
bash AI/run-flutter.sh --photo "/Users/onechamp965gmail.com/Downloads/body_test/image/test/test1.jpg"
```

## 앱에서 확인

1. 이메일 `demo@movid.local`, 최초 기본 비밀번호 `movid1234`로 로그인합니다.
2. 아래 **분석** → **사진으로 분석** → **정면 사진 추가** → **앨범에서 선택**을 누릅니다.
3. 가져온 전신 사진을 고른 뒤 **확인** → **분석 시작**을 누릅니다.
4. 완료되면 원본 Flutter 결과 화면에서 어깨·골반 기울기와 비율을 확인합니다. 분석 기록에서도 조회할 수 있습니다.

시연 계정은 별도 로컬 H2 DB에 원본 회원 API로 생성됩니다. 신체 프로필(170cm·65kg·25세)은 테스트용 기본값입니다. 실제 사용자 신체 정보가 아닙니다. 기존 서버나 실제 서비스의 관리자 계정을 변경하지 않습니다. 반복 테스트용 시연 계정의 일일 한도는 10,000회, 일반 계정은 3회입니다. 성공한 동일 사진 재요청은 저장 결과를 재사용하고, 실패는 한도를 차감하지 않습니다.

## 결과를 읽는 방법

- MediaPipe: 사진에서 관절을 찾아 픽셀 좌표 기반 기울기·비율을 계산합니다.
- DINOv3: 양쪽 상완 사진 특징을 추출합니다. 특징은 AI 응답에 포함되지만 원본 Flutter는 해당 상세 항목을 표시하지 않습니다.
- **균형 점수·체형 분류·근육 발달 등급은 제공하지 않습니다.** 원본 Flutter는 이 값이 없으면 ‘점수 산출 불가’, ‘판정 불가’라는 문구를 표시합니다. 분석 요청 실패와 구분해야 합니다. 숫자 측정값이 보이면 사진 분석 자체는 완료된 것입니다.
- 측면 사진의 목 전방 각도는 현재 연결 경로에서 계산하지 않습니다. 목표 체형 비교, 맞춤 루틴 생성과 홈의 운동 기록 기능은 이번 연결 범위에 포함되지 않습니다. 홈의 해당 카드에는 서버 오류가 보일 수 있습니다.
- 의복·촬영 거리·카메라 기울기에 따라 값이 달라질 수 있습니다. 앱이 사진을 축소한 뒤 업로드하므로 같은 원본의 직접 API 요청과도 약간 다를 수 있습니다.

## 실행 구성과 종료

- `127.0.0.1:8080`: Flutter 연결 API, 실제 AI 엔진
- `127.0.0.1:8082`: 원본 Spring 인증·프로필 서버
- `AI/.runtime/flutter_demo/auth/`: 로컬 H2 계정 DB와 임의 생성 JWT 키
- `AI/.runtime/flutter_demo/bridge/`: 사진·분석 결과 SQLite와 서명 키
- `AI/.runtime/flutter_demo/backend.log`, `ai.log`: 실행 로그

사진·DB·키·모델·가상환경·생성물은 Git에서 제외합니다. 서버는 로컬 주소에만 열립니다. 서명된 사진 링크는 1시간 유효하며 사진 삭제 시 무효화됩니다. 분석·사진 조회와 삭제는 원본 Spring이 검증한 사용자 소유권을 확인합니다.

종료는 실행 터미널에서 `Ctrl+C`입니다. 실행기가 자신이 시작한 서버를 종료합니다. 기존 서버의 사용 중 포트는 자동으로 끄지 않습니다.

```bash
# 서버만 준비: 앱을 별도로 실행할 때
bash AI/run-flutter.sh --no-app

# 다른 포트 사용
bash AI/run-flutter.sh --port 8090 --backend-port 8092 --photo "/사진/test1.jpg"
```

서버만 실행한 경우 Flutter 빌드는 `AI/.runtime/flutter_demo/FE` 복사본에서 `--dart-define=API_BASE_URL=http://127.0.0.1:8080`을 지정해야 합니다. 원본 FE에서 실행해 빌드 파일을 만들지 않습니다. 현재 Xcode 최소 iOS 버전은 AI 외부 설정(`bridge/ios-local.xcconfig`, iOS 15)을 사용합니다. H2 드라이버는 AI Gradle 초기화 파일로 런타임에만 추가합니다.

## 확인한 실행 결과 (2026-10-31)

- 원본 FE/BE 파일 723개 내용 일치 검사 통과
- 원본 Spring 빌드 성공, 로컬 계정 생성·실제 JWT 로그인 성공
- 자동 검사 40개 통과(사진 소유권, 실패 시 한도 미차감, 일반 계정 한도, 인증 응답 오류, DB 실패 시 작업 슬롯 복구 포함)
- 실제 DINOv3 모델 준비 및 분석 완료
- iPhone 16 / iOS 26.5 QA 시뮬레이터에서 원본 Flutter 빌드·실행 성공
- 앱에서 로그인 → 앨범 test1 선택 → 업로드 → 분석 요청 → 결과 표시까지 직접 확인
- 앱 결과: 어깨 0.64°, 골반 1.40°, 어깨/골반 1.73, 상체/하체 약 0.70
- 직접 HTTP로 같은 원본 파일 전송: 어깨 1.01°, 골반 1.52°, 비율 1.75 / 0.73

사진·개인정보가 포함된 실행 스크린샷과 응답은 로컬 `.runtime`에만 보관하며 공개 저장소에는 넣지 않습니다. 실제 휴대폰 카메라 촬영은 아직 검증하지 않았습니다.
