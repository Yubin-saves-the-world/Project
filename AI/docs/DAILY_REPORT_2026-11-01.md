# MOVID AI 개발·검증 보고서

- 작성일: 2026-11-01
- 작업 범위: AI/ 내부 코드·문서·테스트·로컬 실행 자료
- 결론: 사진 측정과 로컬 Flutter 연결은 실제 실행을 확인했습니다. 윤곽 분류는 실행 가능한 미검증 실험 기능이며, 전체 서비스와 건강·체형 판정 기능이 완성됐다는 뜻은 아닙니다.

## 1. 오늘 수행한 작업

### 검수 자료와 재학습

- Kaggle 후보 144장 미리보기를 살펴본 뒤 원본 9장과 상완 크롭 12개를 직접 확인해 라벨링 묶음을 준비했습니다.
- 사용자가 저장한 라벨을 기존 자료와 통합했습니다. 학습 직전의 최신 저장 값을 사용했으며 라벨을 임의 생성하거나 수정하지 않았습니다.
- 통합 검수 항목 59개 중 제외 36개를 빼고 23개 상완 영역을 학습에 사용했습니다.
- 최종 분포는 clear 7 / medium 15 / weak 1입니다. 인물 그룹 16개는 임시 사진별 ID를 포함하므로 검증된 서로 다른 사람 수로 보고하지 않습니다.
- DINOv3는 고정하고 768차원 특징을 이용한 선형 윤곽 분류기만 학습했습니다.
- 기존 모델을 보존하면서 새 모델을 생성·적용했습니다. 정식 재학습 명령의 계수가 이전 임시 학습 스크립트 결과와 일치하는 것을 확인했습니다.

### 재현성과 입력 검증

- 임시 스크립트 대신 train_contours.py의 명시적 fit-only 실행 경로를 추가했습니다.
- 기존 출력 폴더 덮어쓰기와 검수 미완료 자료의 학습을 거절합니다.
- 학습 중 라벨 변경 시 새 모델을 게시하지 않습니다.
- 검수 해시가 있는 원본·크롭은 통합과 학습에서 변경 여부를 확인합니다. 통합 후에도 항목별 증거를 검사합니다.
- 학습·검증·시험으로 지정한 입력을 모두 소비하는 fit-only 특성을 보고서에 기록하고 평가 점수는 생성하지 않습니다.

### 서버·Flutter 연결

- 실제 Spring의 시연 계정 로그인과 AI 측정 서버를 원본 Flutter 앱에 연결했습니다.
- 실행기에 --contour-model 옵션과 분류기 사전 검증을 추가했습니다.
- /health에서 현재 분류기의 SHA256, 등급 목록, 검증 상태를 확인할 수 있습니다. 로컬 파일 경로나 토큰은 반환하지 않습니다.
- 실제 로그인 → 사진 업로드 → 분석 작업 → 결과 조회를 확인하는 verify_flutter_flow.py를 추가했습니다.
- 연결 검사는 로컬 주소만 사용하고 리디렉션과 환경 프록시를 사용하지 않습니다. 완료 후 자신이 올린 검사 사진만 삭제합니다.
- 인증 연결에서도 환경 프록시를 사용하지 않으며, 잘못된 사용자 ID와 문자열·숫자로 전달된 동의 값을 승인으로 취급하지 않도록 보강했습니다.

## 3. 모델 성능을 해석하는 방법

- 새 모델 상태는 not_evaluated입니다.
- weak가 1개 인물 그룹뿐이므로 등급별 최소 3개 그룹을 요구하는 교차검증을 실행할 수 없습니다.
- 현재 모델의 정확도나 F1 개선을 주장하지 않습니다. 기존 11영역 모델의 72.7% 교차검증 수치를 새 모델에 적용하면 안 됩니다.
- 최종 학습에 사용한 23개 영역으로 다시 예측한 값을 독립 시험 정확도로 보고하지 않습니다.
- 후보 점수는 정답 확률·건강 점수가 아닙니다. 판정 보류 기준은 낮추지 않았습니다.
